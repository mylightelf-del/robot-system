### 권한·데이터 분리 (서버 검증)
- 역할 4종 + 사업장 권한 + 고객 제어의 명령별 부여. `src/lib/auth/authz.ts`
- URL/로봇 ID/보고서 ID 조작으로 타 사업장 접근 시 차단(존재 여부 비노출).
- 고객에게 오류 원문·통신 로그·내부 메모·제조사 ID·초안/검토본 비노출.
- 비활성 사용자 전면 차단. 명령 감사 기록(사용자·사업장·로봇·명령·파라미터·시각·결과·추적 ID).

### 운영 규칙
- 명령 상태 요청→접수→실행확인→완료/실패/결과불명. 응답 유실은 결과 불명으로 기록(허위 성공 없음). 만료 명령 재전송 금지.
- 같은 요청 키 중복 거부, 로봇당 처리 중 명령 충돌 거부, 상태 전이 규칙(대기 중 일시정지 불가 등).
- 영역 명령 검증: 지도 버전 불일치(요청/로봇 보고), 모서리 좌표 없음, 범위 밖 다각형, 다른 층 구역, L 시리즈 SWEEP 외 모드 → 전송 차단.
- 실적 중복 제거 키 = 제조사 + 제조사 로봇 ID + 제조사 작업 ID. 로봇 이동 후 과거 실적은 당시 사업장 유지.
- 보고서: 계획 완료율 = 정상 완료 계획 회차 / 유효 계획 회차(취소·제외·미래 제외), 분모 0 은 "해당 없음". 즉시·원격 지시는 별도 집계. 누적 면적은 고유 면적 아님을 표기. 물·세제 미제공은 null. 데이터 미수신 일자·미제공 지표 표기. 확정 시 스냅샷 고정, 늦은 실적은 새 버전.
- 알림: 수신자별 등급·시간대, 중복 억제, 미조치 확대 통보. 발생과 복구를 같은 장애 건에 연결. 모두 모의 발송.
- 시간: UTC 저장, Asia/Seoul 표시, 월 경계는 사업장 시간대.

### 제조사 연동 구조
- `VendorAdapter` 인터페이스 아래 샘플 어댑터만 동작. CenoBots·PUDU 어댑터는 미구현 스텁(호출 시 "미구현" 오류)이며 요청·응답 형식을 추측해 만들지 않았다.
- CenoBots 구현 전 메모를 `src/lib/vendors/cenobots/README.md` 에 정리(문서에서 확인한 endpoint 목록, 주의사항).

## 4. 완료 / 미완료

완료: 위 1장 전체.

미완료 또는 제한(의도적으로 1단계 범위 밖):
- 실제 로그인·세션·비밀번호(2단계). 역할 전환기는 샘플용.
- 영속 저장소(2단계). 서버 재시작 시 샘플로 초기화.
- CenoBots·PUDU 실제 API 호출, 인증키 입력, 실기 명령(3·4·6단계).
- Webhook 수신(복호화·challenge·역순·재시작 복구)과 주기 조회 대조(5단계). 샘플은 버튼 시뮬레이션.
- 실제 이메일·알림톡 발송(5단계). 모의 발송만.
- 서버측 PDF 생성·확정본 파일 보관(5단계). 현재는 브라우저 인쇄.
- 엑셀 내보내기(제안 기능, 미구현).
- 실제 지도 이미지·좌표 변환(제조사 지도 API 연결 후). 현재는 격자형 샘플 구역.
- 예약 실행기(자체 스케줄러)의 실제 실행(2단계 이후). 현재는 예정 회차 생성·표시만.
- 모바일: 반응형 레이아웃 적용(폭 390px 확인). 전용 조작 레이아웃 최적화는 추후.

## 5. 다음 단계 제안 (2단계 "기반")
1. PostgreSQL + 마이그레이션 도구 도입, `StoreData` 를 리포지토리 계층으로 교체. DB 변경 이력 관리.
2. 실제 인증(이메일+비밀번호 또는 SSO), 세션 만료, 사용자 초대·비활성화. 인가 규칙은 현재 `authz.ts` 유지.
3. 환경 분리(dev/staging/prod), 비밀값 관리, 백업·복구 절차, 운영 감시 항목 정의.
4. 배포 대상 후보 비교(단일 VM + Docker vs 관리형 PaaS) — 비용은 조회 후 제시.
