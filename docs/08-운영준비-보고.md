# 08. 운영 준비 — 사업장·층·제조사 지도 관리, 장애 묶음

사용자 결정(2026-10-29): 명령 확인(MT1·CC1)은 뒤로 미루고 운영 준비부터 진행.
실기 데이터로 드러난 공백은 세 가지였다. (1) 실제 사업장·층을 화면에서 만들 수 없었다(샘플 적재뿐). (2) 로봇 위치가 샘플 지도 위에 미터 좌표 그대로 찍혔다. (3) 같은 경고(위치 상실)가 하루 수 건씩 별개 장애로 쌓였다.

## 2. 실기 확인 (2026-10-29, 선릉센터)
PUDU 지도 API 를 실서버에서 호출해 구조를 확인했다(`docs/06` 12장): 선릉 매장에는 지도 10개가 있고, `1#2#포스코센터1층_` 은 1387×1739px, 해상도 0.05m/px, 원점 (-28.10, -80.65), 요소 79개(area 10·source·chargeWorkStation·forbidden), 이미지는 PUDU S3 URL 이다.

브라우저로 운영 절차를 그대로 수행했다(스크린샷 `docs/screenshots/30~33`):
1. 관리 설정 → 사업장 『포스코센터 선릉』 추가 → 층 『1층』 추가(빈 지도 v1).
2. 로봇 사업장 이동으로 선릉 로봇 3대(PW-R-021~023)를 이 층에 배치.
3. 『PUDU 지도 가져오기』 → 목록 10개 중 `1#2#포스코센터1층_` 선택 → 지도 v2 생성, 구역 10개(중앙청소 813.5㎡, 우천시 회전문1~3, 1~6).
4. 다음 폴링에서 충전 중인 1층 로봇이 지도 위 도크 위치(px 558,125)에 표시됐다. 오프라인인 2대는 다른 지도(`-1#1#포스코센터B1층`, `3#1#테스트11`)를 마지막으로 보고해 『지도 불일치』로 표시된다(정상 동작).
5. 콘솔 오류 없음.

## 4. 남은 것·주의
- 지도 이미지는 PUDU S3 URL 을 그대로 참조한다. URL 이 바뀌거나 접근이 막히면 지도가 비므로, 가져올 때 이미지를 우리 서버에 복사해 두는 것이 다음 단계 과제다.
- 구역 다각형은 PUDU 의 `area` 요소 그대로이며, 우리 쪽 편집 기능은 없다(PUDU 앱에서 편집 후 다시 가져오기).
- 층 번호 매핑은 사람이 지도 이름(『층#버전#이름』)을 보고 고른다. 자동 매핑은 하지 않는다.
- 지도를 다시 가져오면 구역이 새 지도 기준으로 교체된다. 등록 작업의 구역 연결(zoneIds)은 PUDU 작업에는 쓰지 않는다.
- 로봇이 보고하는 방향(yaw)은 상세 API 에 없어 삼각형 방향은 0° 로 고정된다.
- 묶음 기준 6시간은 환경변수 `INCIDENT_GROUP_HOURS` 로 조정한다. 고객 화면의 경고(MEDIUM) 노출 기준은 아직 결정하지 않았다.
