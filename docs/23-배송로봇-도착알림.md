# 23. 배송로봇(PUDU FlashBot) 도착 알림 — 에이전트 연동

목적: 배송로봇이 목적지에 도착하면 그 목적지의 **직원**에게 바로 알린다. 수령(로봇 화면 확인)이 늦으면 한 번 더 알린다.
범위(2026-11-13 갱신): 상태·배송 기록·도착 알림 + **Wide Bot 에서 배송 지시·호출·호출 취소**(사용자 결정). 그 밖의 조작(커스텀콜·기계 조작 지령)은 보내지 않는다.
결정(사용자 2026-11-13): 모델은 구형 FlashBot 으로 가정(PRO 아님, SN 8080Y3B27050011, 활성화 2026-11-05), 업체 에이전트로 연결.

자료: Google Drive `PUDU/FLASHBOT` — `정의서/PUDU_Interface.pdf`(도킹서비스 번역본), `정의서/PUDU_API정의서.pdf`(로봇 호출 API 규격서 v1.0), `Agent API Guide_poscowide.pptx`(장치 ID·비밀키·리전·적용 매장), `에이전트 v1.6.8.zip`(실행 파일).
**주의**: PPT 에 비밀키가 그대로 적혀 있다. 이 저장소·문서·대화에는 옮기지 않았다. 서버 `.env` 에만 넣고 PPT 공유 범위를 줄이며, 가능하면 재발급한다.

## 1. 에이전트란
- PUDU 가 주는 실행 파일(리눅스·맥·윈도). 실행하면 9050 포트로 HTTP API 를 연다. 장치 ID·비밀키·리전으로 PUDU 클라우드에 접속한다(장치 하나당 에이전트 하나 — 1:1).
- 장치는 매장(적용 매장: 테스트_포스코빌딩(삼성), 2601_포스코와이드)의 로봇 그룹에 묶이고, 그 로봇의 상태·알림을 받는다.
- 우리 쪽은 에이전트에 「알림 받을 주소」를 등록하고, 에이전트가 배송 임무 알림(notifyDeliveryTask)·이동 상태 알림을 그 주소로 보낸다.
- 에이전트 API 에는 **인증이 없다**(호출·배송 지시·조작까지 가능) → 서버 내부 네트워크에만 둔다(포트를 밖에 열지 않음).
- 지금 청소로봇용 PUDU 키로는 이 배송로봇이 보이지 않는다(SN 조회 401, 시험 매장 미노출) — 그래서 에이전트가 필요하다.

### 동작 규칙
- 배송 구간 = 로봇 · 트레이 · 목적지. 「대기 → 이동 중 → 도착 → 완료/취소」. 상태는 앞으로만 간다. 늦게 온 옛 알림은 무시, 같은 알림 재전송은 중복 제거(msgId).
- **도착 순간 한 번** 알림: 그 사업장의 목적지 수신자 → 없으면 `*`(기본 수신자). 이미 완료·취소된 구간은 보내지 않음.
- **재알림**: 알림 후 `PUDU_AGENT_REMIND_MINUTES`(기본 3분) 안에 완료가 없으면 한 번 더. 받는 사람이 없던 도착은 재알림하지 않음.
- 채널: 앱 푸시(앱에 로그인한 직원만) · 메일(계정 메일) · 카카오톡(본인이 카카오를 연결한 직원만). 목적지 행마다 고른다. 결과는 알림 기록(종류 DELIVERY)과 배송 기록의 「알림」 칸.
- 새 로봇은 「사업장 미지정」으로 나타난다 → 배송 화면에서 사업장을 고른다(미지정이면 알림을 보내지 않고 이유를 남김).

## 4. 운영 반영 순서
1. **업체 확인**: 이 장치 ID 를 업체·다른 곳에서 이미 쓰고 있지 않은지(1:1). 쓰고 있으면 새 장치 발급 요청.
2. **PUDU 클라우드 신청**: 「로봇 배송 임무 상태 알림」(필요하면 이동 상태·전력량) 수신 신청 — 문서상 신청 필요 항목. 대리점에 요청.
3. **실행 파일**: zip 에서 리눅스 실행 파일을 서버 `/opt/robot-system/agent/` 에 둔다(85MB, Drive → 서버. 저장소에 넣지 않음).
4. **.env**: `PUDU_AGENT_MODE=live`, `PUDU_AGENT_URL=http://pudu-agent:9050`, `PUDU_AGENT_BIN=<실행 파일 이름>`, `PUDU_AGENT_DEVICE_ID`, `PUDU_AGENT_DEVICE_SECRET`, `PUDU_AGENT_REGION=ap-southeast-1`, `PUDU_AGENT_NOTIFY_TOKEN=<긴 무작위값>` (`scripts/remote-env.sh`).
5. **기동**: `docker compose --profile delivery up -d pudu-agent` → 배포(web·worker 재시작) → `docker compose run --rm worker npx tsx scripts/delivery-agent-setup.ts`(장치·알림 주소 등록, 로봇 목록 출력).
6. **화면**: 배송 → 로봇 사업장 지정 → 목적지별 수신자 → 실제 배송 1회로 도착 알림·재알림·완료 확인.
7. **끄기**: `PUDU_AGENT_MODE=unconfigured` + 재시작(알림 수신 503, 워커 중지). 에이전트는 `docker compose stop pudu-agent`.

## 6. 카카오 알림톡 — 솔라피(사용자 결정 2026-11-14)
구현: `src/lib/notify/solapi.ts`(HMAC-SHA256 인증, `/messages/v4/send-many/detail`), 알림 경로는 「카카오 채널 + 전화번호」 → 알림톡. 직원은 **내 계정 → 휴대폰 번호**를 입력(마이그레이션 0019 `users.phone`). 배송 수신자 설정에서 「카카오톡」을 고르면, 번호가 있고 솔라피가 설정된 직원은 알림톡, 아니면 「나에게 보내기」(본인 연결)로 간다. 템플릿이 없는 알림 종류는 알림톡을 보내지 않는다(검수 템플릿 밖 문구 발송 불가).

준비 순서(계정주):
1. 솔라피 가입·사업자 인증 → 충전(알림톡 건당 과금).
2. 카카오톡 채널 개설(카카오 비즈니스, 비즈니스 인증) → 솔라피 콘솔 「카카오 채널 연동」 → 발신 프로필 ID(**pfId**).
3. 솔라피 콘솔 「알림톡 템플릿」에 아래 4종 등록 → 검수(보통 1~3 영업일). 버튼(선택): 웹링크 「배송 화면」 https://widebot.kro.kr/delivery
4. (선택) 문자 대체 발송용 발신번호 등록.
5. API 키·시크릿 발급 → 서버 .env 에 `SOLAPI_API_KEY`, `SOLAPI_API_SECRET`, `SOLAPI_PFID`, `SOLAPI_TEMPLATES`(검수된 템플릿 ID JSON), 선택 `SOLAPI_SENDER`.

템플릿 초안(변수 #{…} 그대로, 문구 수정 시 코드의 변수 이름과 맞출 것 — `ALIMTALK_TEMPLATE_DRAFTS`):

| 키 | 내용 |
|---|---|
| DELIVERY_ARRIVED | [Wide Bot] 배송 도착 안내 / 배송로봇이 #{목적지}에 도착했습니다. / - 로봇: #{로봇} / - 도착 시각: #{시각} / 수령 후 로봇 화면에서 확인(완료)을 눌러 주세요. |
| DELIVERY_REMIND | [Wide Bot] 배송 수령 안내 / #{목적지}에 도착한 배송을 아직 수령하지 않았습니다. / - 로봇: #{로봇} / - 도착 시각: #{시각} / 수령 후 로봇 화면에서 확인(완료)을 눌러 주세요. |
| DELIVERY_CANCEL | [Wide Bot] 배송 취소 안내 / #{목적지} 배송이 취소되었습니다. / - 로봇: #{로봇} / 보낸 분께 확인해 주세요. |
| DELIVERY_PROBLEM | [Wide Bot] 배송로봇 이상 안내 / 배송로봇 #{로봇}에 이상이 있습니다. / - 내용: #{내용} / - 시각: #{시각} / 현장 확인이 필요합니다. |
