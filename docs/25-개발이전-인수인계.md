## 1. 회신문 요약

- **무엇**: 포스코와이드 여러 사업장의 청소로봇(PUDU·CENOBOT·BIB)과 배송로봇(PUDU FlashBot·BellaBot)을 본사·현장·고객사가 권한별로 보는 **웹 통합관제 + 안드로이드 앱**. 상태·지도·실적·장애·조치·원격 작업·월간 보고서·알림.
- **운영**: https://widebot.kro.kr — 2026-10-29 가동. PUDU 실연동(live), CENOBOT 모의(mock, 키 대기), 배송 알림 일부 운영.
- **코드**: GitHub `mylightelf-del/robot-system`(공개 저장소), 작업 브랜치 `claude/sharp-bardeen-foe1tf` = `claude/charming-knuth-3nrfet`(항상 같은 커밋). 2026-10-28 시작, 커밋 약 80개.
- **기술**: TypeScript 단일 언어. Next.js 16(App Router)·React 19·Tailwind 4 / Drizzle ORM·PostgreSQL 16 / 별도 워커(Node) / Docker Compose / Caddy(HTTPS). 앱은 Expo(React Native).
- **규모**: 소스 약 2.2만 줄, DB 테이블 43개(마이그레이션 0000~0022), 화면 15개, API 약 50개, 자동 시험 26파일·161건(실제 Postgres 사용, 모두 통과).
- **비용**: 고정비 **월 약 12달러(Lightsail)** + 소액(S3·SES). 그 밖은 무료 등급 또는 미사용(3-5).
- **주요 미완료**: 점검(PM) 계획·목록, CENOBOT 실연동(키 대기), BIB(문서 대기), FlashBot 연결(로봇 측 응답 없음·대리점 확인 중), 카카오 알림톡(솔라피 검수 대기), Teams 봇 발송(코드 완료·미배포, Azure 등록 대기), 앱 스토어 등록.
- **넘겨받을 것(비밀값)**: 서버 `.env`(각종 키), AWS 프로젝트 접근, GitHub 저장소 권한·Secrets, PUDU 대리점 계정, Firebase·Play Console. 2-5 표.

### 3-4. 배포 방식
1. 코드 푸시(작업 브랜치 두 곳) → 2. GitHub Actions `ops` 실행(action=`deploy`, ref=브랜치) → 3. 러너가 소스 묶음을 S3 에 올리고 SSM 으로 서버에 「받기 → `docker compose build` → 마이그레이션(migrate 서비스) → 사전 점검(preflight) → 재기동」 → 4. health JSON 확인. 5~10분.
- 배포 전 DB 백업 권장: `ops/` 스크립트 또는 `scripts/backup.sh`. 되돌리기는 이전 커밋 재배포 + 필요 시 `scripts/restore.sh`.
- 설정만 바꿀 때: GitHub Secrets 등록 → action=`sync-secrets`(web·worker 재시작).

## 4. 데이터 구조

### 4-1. 개요
- PostgreSQL 16, 스키마 원본 `src/lib/db/schema.ts`, 마이그레이션 `drizzle/0000~0022`(전부 **추가 방식** — 기존 열 변경·삭제 없음).
- 시간은 UTC 저장, 표시는 사업장 시간대(Asia/Seoul). 제조사 원시 상태와 공통 상태를 함께 저장. 로봇이 사업장을 옮겨도 과거 실적은 당시 사업장에 남는다.
- 비밀 토큰(세션·API 토큰)은 해시로만 저장, 카카오 토큰은 암호화(`TOKEN_ENCRYPTION_KEY`).

### 4-2. 테이블(43개)과 관계
| 분류 | 테이블 → 참조 |
|---|---|
| 사업장·공간 | `sites` ← `floors`(sites) ← `zones`(floors), `map_versions`(floors) ← `map_images`(map_versions) |
| 로봇 | `robots`(sites, floors) ← `robot_status`(1:1), `robot_placements`(배치 이력), `maintenance_history`, `maintenance_items`(소모품), `inspections`(점검, sites·robots) |
| 작업·실적 | `registered_tasks`(robots, sites) ← `schedules`(예약); `planned_runs`(예정 회차); `actual_runs`(실적, 제조사 작업 ID 로 중복 제거) ← `run_images`(결과 지도) |
| 명령 | `commands`(robots, sites; 요청→접수→실행확인→완료/실패/결과불명) |
| 장애 | `incidents`(robots, sites) ← `incident_actions`(조치 단계), `incident_photos`, `notification_logs`(장애 통보일 때) ; `severity_overrides`(등급 사용자 정의) |
| 보고서 | `report_versions`(sites; 초안→검토→확정, 수치 수정 이력) ← `report_photos` |
| 사용자·권한 | `users` ← `site_permissions`(users×sites, 허용 명령), `sessions` ← `push_devices`(앱 기기), `kakao_links`, `api_tokens`(외부 조회용 오픈 API) |
| 알림 | `notification_settings`(사업장별) ← `notification_recipients`(채널·종류·등급·시간대) ; `notification_logs`(모든 발송 결과) |
| 연동 | `vendor_connections`, `vendor_events`(콜백 원문·처리 결과), `vendor_sync_state`(작업별 마지막 성공·오류), `app_settings`, `audit_logs`(모든 명령·관리 변경) |
| 배송 | `delivery_robots`(sites; source=agent\|openplatform) ← `delivery_legs`(트레이·목적지 구간: 대기→이동→도착→완료/취소), `delivery_orders`(지시 기록), `delivery_events`(알림 원문) ; `delivery_recipients`(사업장×목적지 → 수신자), `delivery_presets`(즐겨찾기 배송) |
| Teams | `teams_conversations`(직원별 Teams 봇 개인 채팅 주소, 0022·미배포) |

핵심 흐름: **로봇 → (폴링·콜백) → `robot_status`·`actual_runs`·`incidents` → 대시보드·보고서·알림**. 명령은 `commands` 와 `audit_logs` 에 남는다. 권한은 모든 조회·명령에서 `site_permissions` 로 서버가 검사한다.

## 7. 개발 프롬프트 요약(인수인계)

### 7-1. 최초 지시(요지, 원문 `docs/HANDOFF.md` 0장)
> 이 문서를 인수인계 기준으로 읽고 개발을 진행. 나는 프로그래밍 초보이며 운영 관점에서 검토. 확정 요구사항은 다시 묻지 말고 미정은 제안+근거. 1단계는 5개 가상 사업장·20대 **샘플임을 명확히 표시**한 시제품(역할별 화면·사업장 접근 범위·작업 상태·장애 조치·보고서 확정 흐름). **실제 API 모듈과 샘플 모듈 분리, API 주소·응답을 추측해 구현하지 말 것**, 실제 키·로봇 명령은 시제품에 포함하지 말 것. 코드와 함께 실행 방법·환경변수 예시·시험 결과·완료/미완료를 남길 것.

### 7-2. 계속 지킨 원칙(모든 단계 공통)
- 비밀값은 서버 `.env` 에만(저장소·문서·로그·화면 금지). 샘플에 실제 고객 정보 금지.
- 고객에게 원시 오류·내부 메모·초안 비공개, 서버에서 사업장 범위 검사, 모든 명령 감사 기록.
- HTTP 성공을 작업 완료로 보지 않음(명령 상태 단계), 중복·만료 명령 재전송 금지.
- 시험하지 않은 것을 통과했다고 쓰지 않음, 시뮬레이션은 표시.
- 실제 로봇 명령은 소유자가 허락한 조건에서만(현재 중지). 로봇의 지도·층을 시스템이 바꾸지 않음.
- 마이그레이션은 추가만, 연동은 설정값으로 끌 수 있게(코드 되돌림 없이).
- AWS 자원은 ap-southeast-2 에만. 사용자에게는 한국어로.

### 7-3. 단계별 주요 요청(시간순 요약)
1. 1단계 시제품 → 2단계 기반(DB·로그인·권한·감사·워커·Docker) → 3단계 PUDU 연동(상태·보고서·장애·작업·예약·소모품·명령·콜백·지도) → AWS 배포(10-29).
2. 보고서 개편(버튼 작성·수치 수정·PPT/Excel·설치 보고서), 보고서 일정, 알림 발송(SES·카카오), 전체 점검·고급 설정 분리, 올해 데이터 적재, 원격 제어 스위치, 사용 중지.
3. 개선 A(자동 메일·미실행/무실적 알림·KPI·오늘 할 일·PWA·구독), 개선 B(청소 범위 증빙·조치 가이드·소모품 예측·오픈 API·조치 사진), 디자인 개편 4차, 안드로이드 앱.
4. CENOBOT·BIB 연동 프롬프트(0단계 구조 조사·계획 → 1단계 어댑터 mock → 3단계 점검 → 4단계 운영 반영: 백업·키 보관·외부 연결·웹훅·시간 동기화·mock 우선·설정으로 끄기·원격 제어 유지). 조회 전용.
5. 배송로봇 도착 알림(에이전트 방식, 목적지별 수신자·재알림 1회·실패/취소/막힘 알림·배송 지시·통계·즐겨찾기), 솔라피 알림톡, 신형(오픈플랫폼) 경로.
6. 운영 편의: GitHub Actions 로 로그인 없는 배포·점검·비밀값 반영. Teams 개인 알림(워크플로 → 지연 우려로 봇 직접 발송).

## 8. 구축 가이드(새 서버에 처음부터)

1. **서버**: Ubuntu 24.04, 2GB RAM 이상(빌드용 스왑 2GB), Docker·Docker Compose 설치. 방화벽 80·443 개방(관리 채널은 SSM 권장, SSH 는 닫거나 제한).
2. **코드**: `/opt/robot-system` 에 저장소 배치(`deploy-remote.sh` 는 소스 묶음을 받아 교체).
3. **설정**: `.env.example` 을 `.env` 로 복사 → 필수: `APP_ENV=production`, `DOMAIN`, `APP_BASE_URL`, `ACME_EMAIL`, `DATABASE_URL`(compose 의 db), `POSTGRES_*`, `TOKEN_ENCRYPTION_KEY`, `VENDOR_MODE`. 제조사·알림 키는 연동할 것만. `chmod 600 .env`.
4. **기동**: `docker compose up -d` → migrate 서비스가 마이그레이션 적용·사전 점검(preflight) → web·worker·caddy 기동, 인증서 자동 발급. `curl https://<도메인>/api/health` 가 `"db":"up","worker":"up"`.
5. **관리자**: `docker compose run --rm worker npx tsx scripts/bootstrap-admin.ts "이름" 이메일` → 출력된 초대 링크(72시간·1회)로 비밀번호 설정.
6. **사업장·로봇**: 관리 설정 → 고급 설정에서 사업장·층·로봇 등록, PUDU 연결 시 `PUDU_SHOP_IDS` 설정 → 「지도 가져오기」 → 과거 실적 `scripts/pudu-backfill.ts --from YYYY-MM-DD` → `scripts/recompute-drafts.ts`.
7. **콜백**: PUDU 콜백 주소 `https://<도메인>/api/webhooks/pudu`(대리점에 등록, 받은 코드 `PUDU_CALLBACK_CODE`). CENOBOT 웹훅 `/api/webhooks/cenobots`.
8. **백업**: cron 으로 `scripts/backup.sh`(매일, 14일 보관) + Lightsail 자동 스냅샷. 복구는 `scripts/restore.sh`.
9. **GitHub 운영 작업**(선택): IAM 사용자(서버 SSM 명령·배포 버킷만) 키를 저장소 Secrets 에 등록, `ops.yml` 을 기본 브랜치에 둔다.
10. **앱**: `mobile/README.md` — Firebase 프로젝트·`google-services.json`, 컨테이너 빌드 스크립트, Play Console 업로드(`docs/21` 14장).
11. **점검**: `npm test`(161건), `scripts/preflight.ts`, `ops/health-delivery.sh`·`ops/agent-check.sh`.
