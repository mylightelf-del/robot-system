# 18. 개선 A — 보고서 발송·운영 알림·KPI·오늘 할 일·PWA·알림 구독 (2026-11-07)

`docs/17` 개선 목록의 A 항목 6개를 구현·배포했다(마이그레이션 0012, 시험 99개 통과).

## 1. 알림 체계 변경(공통)
- 수신자(관리 설정 → 알림 수신 설정)마다 **받을 통보 종류**를 고른다: 장애 발생·복구 / 미조치 확대 통보 / 예정 작업 미실행 / 장기간 무실적 / 보고서 발행. 기존 수신자는 전부 받는 것으로 시작한다.
- 등급·수신 시간대는 장애 통보에만 적용된다. 보고서 발행 통보는 시간대와 무관하게 보낸다.
- 발송 기록(`notification_logs`)이 장애 외 통보도 담는다(`kind`, `refId`). 같은 대상에는 한 번만 보낸다(억제 기록도 포함).
- 이메일에 **첨부**가 붙을 수 있다(SES Raw MIME, 직접 만든 multipart). 카카오톡은 요약과 링크만.

## 2. 항목별

| A2 미실행 알림 | 워커 10분 주기. 자동 판정으로 '미실행'이 된 계획 회차(최근 24시간)를 사업장 수신자에게 **한 번** 통보. 사용 중지 로봇·사업장 제외. 수신자가 없어도 기록을 남겨 다시 보지 않음 | 자동 |

## 3. 운영에서 할 일
1. 관리 설정 → 알림 수신 설정에서 사업장별 수신자의 **통보 종류**를 정리한다(예: 고객 이메일은 '보고서 발행'만, 현장 담당자는 장애·미실행·무실적).
2. **무실적 통보 시간**을 사업장별로 정한다(예: 48시간). 0 이면 꺼져 있다.
3. 보고서는 **고객 공개** 때 자동 발송된다. SES 가 샌드박스라 **확인된 주소에만** 실제로 간다(`docs/13`). 프로덕션 접근 승인 전에는 수신자 주소를 SES 에서 확인하거나 재신청이 필요하다.
4. 폰: Chrome/Safari 에서 widebot.kro.kr 접속 → 공유/메뉴 → 홈 화면에 추가.

## 4. 콜백(PUDU) — 아직 미적용
- 콜백은 대리점이 PUDU 플랫폼에 우리 URL(`https://widebot.kro.kr/api/webhooks/pudu`)을 등록하면 PUDU 가 돌려주는 **`callback_code`** 를 서버 `.env` 의 `PUDU_CALLBACK_CODE` 에 넣어야 동작한다(코드가 없으면 endpoint 가 503 으로 거부).
- 2026-11-07 확인: 메일함에 코드 없음, 서버 접속 로그(최근 7일)에 PUDU 쪽 호출 0건. 등록이 됐다면 로봇이 작업을 시작·종료할 때 호출이 와야 하므로, **URL 등록이 아직 안 됐거나 다른 URL 로 됐을 가능성**이 있다.
- 받을 것: 대리점에서 `callback_code` 값과 등록한 URL. 받으면 `./scripts/remote-env.sh PUDU_CALLBACK_CODE=<코드>` → 관리 설정 → PUDU 패널 『콜백 URL 자가 점검』 → 『최근 수신』 갱신 확인.
