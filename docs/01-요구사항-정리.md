# 01. 요구사항 이해 · 구현 구조 · 미확인 사항

기준 문서: `docs/HANDOFF.md` (청소로봇 통합관제 — Claude 개발 인수인계 v1.0, 2026-10-27)
작성일: 2026-10-28

## 1. 요구사항 이해 (확정 사항 — 다시 묻지 않음)

| 항목 | 이해한 내용 | 시제품 반영 |
|---|---|---|
| 규모 | 5개 사업장, 20대. 실제 배치 미제공 | 가상 사업장 5곳 · 20대 샘플(MT1 6 · CC1 5 · BG1 4 · L4 5). 실제 배치 아님을 화면에 명시 |
| 대상 | PUDU MT1·CC1·BG1, CenoBots L4. BIB J40 보류 | 4개 모델 샘플. BIB 는 제조사 연결 목록에 "보류"로만 표시 |
| 사용자·권한 | 본사 관리자 / 현장 담당자 / 고객 기본 / 고객 제어. 개인 계정에 지정 사업장 권한 부여 | 역할 4종 + 사업장별 권한 + 고객 제어의 명령별 부여. 서버 인가 검증 |
| 화면 | 7개 (대시보드·사업장 관제·로봇 상세·작업·장애·보고서·관리) | 7개 화면 모두 구현(+ 사업장/로봇 목록 보조 화면) |
| 작업 제어 | 실행·예약·중지·복귀, 지도 영역 지정 | 실행·일시정지·재개·중단·복귀·영역 청소(구역/사용자 정의 다각형). 제조사별 의미 표 |
| 보고서 | 월간 4쪽 양식 신규 설계, 초안→의견→검토→확정→공개/PDF | 4쪽 구성 + 흐름 + 브라우저 인쇄(PDF). 확정 스냅샷, 늦은 실적은 새 버전 |
| 알림 | 이메일/알림톡, 공급사 미정 | 교체 가능한 발송 모듈, 모의 발송 + 억제 사유 기록 |
| 제외 | 수동 원격 운전, 카메라, FMS/승강기/자동문 | 미구현(설계에도 포함하지 않음) |

## 2. 구현 구조 (1단계)

```
src/
  app/                 Next.js App Router 화면 + 서버 액션(actions.ts)
  components/          화면 부품 (지도 SVG, 명령 패널, 장애/보고서/관리 패널)
  lib/domain/          엔터티 타입, 공통 상태 우선순위, 제조사별 명령 의미
  lib/auth/            샘플 세션(쿠키) + 인가 규칙(authz.ts) — 모든 접근을 서버에서 검증
  lib/services/        업무 로직 (대시보드·로봇·명령·장애·작업·보고서·관리·감사)
  lib/vendors/         어댑터 인터페이스 / sample(시뮬레이션) / cenobots·pudu(미구현 스텁 + 메모)
  lib/notify/          알림 발송 모듈(모의)
  lib/store/           메모리 저장소(1단계 전용) + 실적 중복 제거
  lib/sample/seed.ts   샘플 데이터 생성기
tests/                 vitest — 인가·명령·보고서 필수 테스트
docs/                  인수인계·요구사항·단계 보고
```

기술 선택과 근거:
- **Next.js + TypeScript 단일 앱**: 화면과 서버 API(서버 액션)를 한 프로젝트로 관리. 20대 규모에 충분하며 저비용 호스팅(Vercel·Railway·단일 VM)에 바로 배포 가능. 제조사별 모듈은 어댑터로 분리하되 서비스 전체를 분산하지 않음(문서 10장 원칙).
- **메모리 저장소**: 1단계는 영속 저장 없이 샘플 흐름 확인이 목적. 서비스 계층은 `StoreData` 형태만 의존하므로 2단계에서 PostgreSQL 로 교체.
- **서버 인가**: UI 숨김과 별개로 `authz.ts` 가 사업장 범위·역할·명령별 권한·활성 여부를 검증. 서버 액션은 직접 POST 로도 호출될 수 있으므로 모든 액션이 다시 검증한다.
- **명령 상태**: 요청→접수→실행확인→완료/실패/결과불명. HTTP 접수만으로 완료 처리하지 않음. 만료 명령 재전송 금지. 중복 키·처리 중 충돌 거부.
- **시간**: UTC 저장, 사업장 시간대(Asia/Seoul) 표시. 월 경계는 사업장 시간대 기준.

## 3. 샘플에서 "시뮬레이션"으로 표시한 것
- 모든 로봇 명령(샘플 어댑터). 정상 접수 / 응답 유실 / 제조사 거부 시나리오 선택 가능.
- 상태 변화(청소 진행·배터리·복귀 도착·작업 완료 실적 생성).
- 장애 발생(Webhook 대신 버튼), 알림 발송(모의), 이벤트 ID 중복 무시.
- PUDU 명령 지원 여부(모델별 API 미검증 → "문서 미검증" 표시), L4 유지관리 수치(샘플).
- 지도: 실제 지도 이미지 대신 격자형 샘플 구역. 모서리 좌표 없는 구형 지도 1개(가상 사업장 3 의 3F)를 두어 차단 동작을 보여줌.

## 4. 미확인 사항 (시제품을 막지 않음, 추후 입력 필요)
- 실제 사업장명·층·구역·로봇 배치, 모델별 대수.
- CenoBots: 현행 문서 버전(V1.0.18 vs v1.0.8 표기 불일치), 실제 서버 지역, 키 권한, 호출 제한, L4 펌웨어가 제공하는 필드, 서명 규칙의 쿼리 포함 여부, 예약 시간대 해석.
- PUDU: MT1·CC1·BG1 별 Cloud API 지원표·인증·명령 규격.
- 알림 공급사(이메일/알림톡), 발신 설정, 템플릿, 과금. 수신 시간대·등급 기준값.
- 클라우드 공급사·예산·보관기간·백업 목표·운영 담당자.
- 로고·시각 디자인·보고서 최종 양식(엑셀 내보내기 여부).
- 현장 담당자의 보고서 확정 권한 허용 여부(현재 설정값: 불가, 관리 설정에서 변경 가능).

## 5. 제안 (미확정이므로 근거와 함께)
- 보고서 PDF: 1단계는 브라우저 인쇄. 5단계에서 서버측 PDF(예: Playwright/Chromium 렌더링)로 확정본 파일을 저장·보관하는 방식을 제안. 근거: 확정본 파일을 버전과 함께 보존해야 하고, 고객이 다운로드할 때 화면과 동일한 결과를 보장하기 쉬움.
- 명령 충돌 정책: 로봇당 처리 중인 제어 명령이 있으면 다른 사용자의 명령을 거부(현재 구현). 본사 우선 등 우선순위 정책은 운영 협의 후 결정.
- 알림 임계값(중복 억제 30분, 미조치 확대 60분)은 사업장별 설정값이며 확정값이 아님.
- 상태 수신 지연 기준(15분 초과 시 "마지막 수신 초과")은 대시보드 설정값으로 두었으며, 제조사 하트비트 주기 확인 후 조정.
