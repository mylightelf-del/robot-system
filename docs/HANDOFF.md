# 청소로봇 통합관제 — Claude 개발 인수인계

기준일: 2026-10-27 / 버전: 1.0
목적: 포스코와이드의 여러 사업장 청소로봇을 본사·현장·고객사가 권한별로 관리하는 외부 클라우드 웹 시스템 개발.
현재 단계: 요구사항 협의 및 CenoBots 공개 API 문서 검토 완료. 제품 코드·실제 인증·실기 시험·클라우드 배포는 아직 수행하지 않았다.

## 0. Claude에게 처음 보낼 요청

이 문서를 프로젝트의 인수인계 기준으로 읽고 개발을 진행해줘. 나는 프로그래밍 초보이며, 운영 관점에서 함께 검토하고 싶다. 이미 확정한 요구사항을 다시 질문하지 말고, 미정 사항은 합리적인 제안과 근거를 제시해줘.

먼저 요구사항 이해, 구현 구조, 미확인 사항을 간략히 정리하고 1단계 시제품을 구현해줘. 5개 가상 사업장·총 20대 샘플 데이터를 사용하고, 샘플임을 명확하게 표시해줘. 샘플의 사업장명·모델별 대수는 실제 배치 정보로 간주하지 마. 역할별 화면, 사업장별 접근 범위, 작업 상태 변화, 장애 조치, 보고서 검토·확정 흐름을 확인할 수 있게 만들어줘.

실제 API 연결 모듈과 샘플 모듈을 분리하고, API 주소·요청·응답을 추측해서 실제 구현처럼 만들지 마. CenoBots는 아래 공식 문서를 직접 확인하고, PUDU는 상세 문서를 추가 검토해. BIB는 후속 검토로 남겨줘. 실제 인증키 입력이나 로봇 명령 전송은 시제품 작업에 포함하지 마.

코드뿐 아니라 실행 방법, 환경변수 예시(비밀값 제외), 테스트 결과, 완료/미완료 항목을 남겨줘. 파일 생성·실행이 가능한 개발 환경이면 구현과 실행 확인까지 수행하고, 채팅만 가능한 환경이면 저장소 파일 구조와 파일별 코드 및 실행 절차를 제공해줘. 기존 저장소가 제공되면 먼저 그 구조와 지침을 확인해줘.

## 1. 확정 범위와 제외 범위

| 항목 | 확정 내용 |
|---|---|
| 운영 규모 | 5개 사업장, 총 20대. 사업장·모델별 실제 배치는 미제공 |
| 초기 대상 | PUDU MT1·CC1·BG1, CenoBots L4 |
| 후속 검토 | BIB J40. 삭제된 대상이 아니라 연동 검토 보류 |
| 환경 | 외부 클라우드, PC·모바일 대응 웹 |
| 사용자 | 본사, 현장 담당자, 고객사 사용자 |
| 고객 계정 | 사업장별 고객 접근. 개인 계정에 지정 사업장 권한 부여 방식으로 설계 |
| 고객 기본 권한 | 자기 사업장의 현황·실적·확정 보고서 조회 |
| 고객 추가 권한 | 별도로 허용된 작업 제어 기능 |
| 주요 기능 | 통합 상태 관제, 청소 실적, 장애 알림·조치, 원격 작업 지시 |
| 작업 제어 | 등록 작업 실행·예약·중지·복귀, API 지원 시 지도 영역 지정 |
| 보고서 | 기존 양식 없음. 고객 제출용 월간 양식 신규 설계 |
| 알림 | 이메일 또는 카카오 알림톡. 공급사·비용·발신 설정 미정 |
| 제외 | 조이스틱 등 수동 원격 운전. 향후 보안로봇 프로젝트에서 검토 |

실시간 카메라 영상은 이번 범위에 포함하지 않는다. FMS·승강기·자동문 연동은 현재 확정 범위가 아니다. 클라우드 공급사, 기술 스택, 예산, 서비스 수준, 보관기간은 아직 확정하지 않았다.

## 2. 화면 구성

1. 종합 대시보드: 사업장별 로봇 대수, 청소·충전·대기·오류·통신 끊김, 당일 실적, 미조치 장애.
2. 사업장 관제: 사업장·층·지도 선택, 위치·방향·배터리·작업 진행·마지막 수신 시각.
3. 로봇 상세: 제조사·모델·내부 관리번호, 작업·장애 이력, 지원되는 명령, 유지관리 정보.
4. 작업·일정: 등록 작업, 예약, 실행·일시정지·재개·중단·복귀. 각 명령은 API별 의미를 구분.
5. 장애·조치: 발생·확인·담당자 지정·조치 등록·복구, 알림 발송 상태.
6. 실적·보고서: 필터, 계획 대비 실적, 월간 보고서 초안·검토·확정·PDF. 엑셀 내보내기는 제안 기능.
7. 관리 설정: 사업장·층·구역·로봇·사용자·제어권한·알림수신·제조사 연결 관리.

디자인 제안(미확정): 한국어 우선, 화이트·네이비, 상태색은 텍스트/아이콘 병용. 모바일은 조회와 작업 조작에 맞춘 레이아웃. 내부 API 코드·인증 설정은 고객 화면에 노출하지 않는다.

## 3. 권한과 데이터 분리

| 역할 | 조회 범위 | 제어 | 보고서 | 관리 |
|---|---|---|---|---|
| 본사 관리자 | 전체/지정 사업장 | 허용 범위 | 작성·검토·확정 | 사업장·계정·연동 |
| 현장 담당자 | 담당 사업장 | 허용 범위 | 작성·확정 권한 설정 | 장애 조치·점검 |
| 고객 기본 | 지정 사업장 | 불가 | 확정본 조회·다운로드 | 없음 |
| 고객 제어 | 지정 사업장 | 명령별 별도 부여 | 확정본 조회·다운로드 | 없음 |

서버에서 모든 목록·상세·지도·명령·보고서 파일 접근의 사업장 범위를 검증한다. URL/로봇 ID 조작으로 타 사업장 접근이 가능해서는 안 된다. 고객 사용자에게 내부 오류 원문·통신 로그·내부 정비 메모·보고서 초안을 노출하지 않는 안을 기본 설계로 삼는다.

명령 감사 기록: 사용자, 사업장, 로봇, 명령, 파라미터, 요청 시각, 결과, 제조사 추적 ID. 사용자 비활성화 시 접근을 차단한다. 샘플 화면의 역할 전환기는 실제 인증/인가를 대신하지 않는다.

## 4. 운영 규칙과 데이터 모델 제안

핵심 엔터티: 사업장, 층, 구역, 사용자, 사업장 권한, 제조사 연결, 로봇, 로봇 배치 이력, 지도 버전, 등록 작업, 예약, 예정 작업 회차, 실제 작업, 명령, 장애, 조치, 알림 발송, 점검, 보고서 버전, 감사 로그.

- 로봇은 제조사 ID와 내부 ID를 별도 보유. 다른 사업장으로 이동하면 과거 실적은 당시 사업장에 남긴다.
- 실제 작업 ID로 실적을 중복 제거. 제조사/계정/로봇 범위를 포함한 키를 검토한다.
- 원시 상태와 공통 상태를 모두 보관. 상태 불명·데이터 미수신·미지원과 수치 0을 구분한다.
- 청소·충전·오류 상태의 우선순위를 정의하고, 마지막 수신과 데이터 발생 시각을 구분한다.
- 명령은 요청·접수·실행확인·완료·실패·결과불명 상태로 관리. HTTP 성공만으로 실제 작업 완료 처리하지 않는다.
- 명령 충돌·중복을 방지하고 만료된 명령은 재전송하지 않는다. 응답 유실 시 로봇 상태/작업 이력을 확인한 후 재시도를 판단한다.
- 제조사 예약과 자체 예약 실행기가 동시에 같은 작업을 실행하지 않도록 단일 실행 주체를 정한다. CenoBots는 제조사 예약 API 활용을 우선 제안한다.
- 휴일·제외일·작업 취소 사유와 계획 변경 이력을 관리한다. 예정 작업 회차와 실제 수행을 연결해야 미실행 작업을 찾을 수 있다.
- 시간은 UTC 저장·사업장 시간대 표시를 기본 제안. 한국 운영 보고는 Asia/Seoul 기준이며 제조사 예약의 시간대 해석은 시험한다.
- API 키는 서버 비밀 설정에만 보관. 제조사 계정의 권한을 고객 계정으로 직접 전달하지 않는다.

## 5. 월간 고객 보고서

기본 4쪽, 표가 길면 자동 확장:
1. 사업장·기간·운영 대수·주요 실적·종합 의견.
2. 계획 대비 수행, 층·구역별 실적, 미완료 사유.
3. 주요 장애·운영 영향·조치, 점검·소모품 기록.
4. 개선 사항·집중 관리 구역·차월 계획.

흐름: 자동 집계 → 현장 의견 작성 → 검토 → 확정 → 고객 공개/PDF.
확정 시 집계값과 의견을 스냅샷으로 보존. 늦게 수신한 데이터로 기존 확정본을 덮어쓰지 않고 새 버전을 작성한다.

지표 기준 제안:
- 계획 완료율 = 정상 완료된 계획 회차 / 유효 계획 회차 × 100. 분모 0은 해당 없음. 취소·제외 규칙은 표시하고 변경 이력을 남긴다.
- 즉시 지시 작업은 별도 집계하여 계획 완료율을 부풀리지 않는다.
- 누적 청소 면적은 중복 구역 반복 작업을 포함할 수 있으므로 고유 청소 면적으로 표현하지 않는다.
- 제조사별 작업·청소·충전·일시정지 시간 정의와 단위를 확인한 뒤 합산한다.
- 데이터 누락 기간과 미제공 지표를 표시한다. 청소 면적만으로 청결 품질·인건비 절감액을 단정하지 않는다.
- API 제공 시 물(L)·세제(mL)·작업 결과 이미지를 선택 항목으로 반영. 실제 값 제공 여부를 검증한다.

## 6. 알림·점검

사업장별 수신자, 장애 등급, 수신 시간대, 중복 억제, 미조치 확대 통보를 설정할 수 있게 한다. 숫자 임계값은 운영 설정으로 두고 확정값처럼 하드코딩하지 않는다.
장애 발생과 복구는 같은 장애 건으로 연결. 상태 이벤트와 고객 통보를 분리하여 모든 이벤트를 알림톡으로 보내지 않는다.
이메일·알림톡은 교체 가능한 발송 모듈로 설계. 시제품 발송은 모의 처리로 표시한다. 실제 채널 가입·발신·템플릿·과금 조건은 선택 공급사 문서로 확인한다.
물 보충·오수 처리·브러시 청소 등의 현장 점검표를 모델별로 설정. API 미제공 점검은 수기 기록한다.

## 7. CenoBots 문서 검토 결과 — 실제 시험 전

공식 문서: https://operation.cz-robots.com/doc/open_api#robot-open-api
해당 페이지가 실제 로드한 문서: https://operation.cz-robots.com/open_api_markdown/open_261022.html
2026-10-27에 공개 HTML 본문을 확인했다. 변경 이력에 V1.0.18(2026-10-10)이 있고, 본문 헤더의 Version에는 v1.0.8도 남아 있어 버전 표기가 일관되지 않는다. 구현 직전 현행 문서를 다시 확인한다.

### 인증·지역
- 문서 예제는 X-Api-Key, X-Api-timestamp, X-Api-signature 헤더를 사용한다.
- 예제 서명은 Secret Key를 사용한 HMAC-SHA256이며 HTTP method + 밀리초 timestamp + URL path를 결합한다. 쿼리 포함 여부 등 상세 규칙은 현행 문서/시험으로 확인한다.
- 지역 HOST: APAC https://app-server-apac.cz-robots.com / EU https://app-server-eu.cz-robots.com / US https://app-server-us.cz-robots.com / 기타 https://app-server.cz-robots.com.
- 한국이라는 이유만으로 APAC를 확정하지 말고 실제 계정 서버 지역을 확인한다.
- 실제 시험에 API Access Key, Secret Key, 로봇 Open ID가 필요하다. 대화·저장소에 비밀값을 붙여 넣지 않는다.

### 확인한 API와 적용
| 기능 | 문서에서 확인한 항목 | 구현 포인트 |
|---|---|---|
| 로봇 상태 | GET /app/openapi/v1/device/status/{deviceOpenId} | online, soc, running, charging, pose, 지도, missionTaskDetail 등 |
| 로봇 정보 | GET /app/openapi/v1/device/info/{deviceOpenId} | 시리얼·소프트웨어 버전·건물명 등 |
| 임시 청소 | POST /app/openapi/v1/mission | mapId, mapVersion, areaIds 또는 userDefinedArea 등 |
| 집계 | POST /app/openapi/v1/mission/summary | 건수·시간(min)·면적(m²)·물(L)·세제(mL) |
| 작업 이력 | POST /app/openapi/v1/mission/list | 페이지 조회, 기간, 결과·종료 사유·이미지·구역 등 |
| 지도 이미지와 좌표 | GET /app/openapi/v1/map/pic-with-points | 이미지 크기·URL·네 모서리 좌표 |
| 유지관리 | GET /app/openapi/v1/device/maintenance-detail/{deviceOpenId} | 잔여수명·초기화 이력 |
| 예약 | Schedule 장의 생성·변경·활성화·목록·삭제 | 각 endpoint와 형식은 원문 참조 |
| 등록 작업 | Favorite 장의 생성·수정·삭제·실행·목록 | 즐겨찾기 작업 연결 |
| 작업 제어 | Go home / Stop / Pause / Continue current mission | 서로 다른 의미를 UI에서도 구분 |
| 지도·구역 | Map 장의 지도 목록·구역 목록·이미지 | 지도 버전별 좌표 연결 |
| 오류·이벤트 | Device 오류 조회 및 Webhook 구독 API | 발생·해제와 상태 업데이트 |

L 시리즈 임시 작업은 SWEEP 모드만 가능하다고 문서에 명시되어 있다. 다른 시리즈 예제의 PATROL을 L4에 그대로 사용하지 않는다.
userDefinedArea는 지도 안의 닫힌 영역 좌표 배열이다. 새 영구 지도를 작성하는 기능과는 구분한다. 지도 모서리 좌표는 좌하·좌상·우상·우하 순서이며 로봇 위치와 같은 좌표계다. 오래된 지도는 좌표가 null일 수 있다. 이 경우 검증된 좌표 변환 없이 영역 명령을 전송하지 않는다.
상태의 pose는 온라인 시 현재 위치, 오프라인 시 마지막 보고 위치다. 화면에서 구분한다.
상태 응답의 consumablesStatistics는 SP50 전용이라고 되어 있으므로 L4 소모품 표시 근거로 사용하지 않는다. 별도 maintenance-detail 응답은 L4에서 시험한다.
문서 예제에는 JSON 쉼표 누락, 값·설명 불일치, VERY_QUIET/VERY_QUITE 표기 차이 등이 있다. 예제 전체를 복사하지 말고 규칙과 실제 응답을 확인한다. HTTP 코드와 body.success/code도 구분한다.

### Webhook
- 오류, 위치, 작업 상태, 유지관리, 문 통과 도움 요청 이벤트가 문서에 있다. 문 도움 이벤트 존재는 자동문 제어 지원을 의미하지 않는다.
- 구독은 API 키에 연결된 회사 범위다. 회사 범위 이벤트를 로봇→사업장 매핑으로 분배한다.
- 공개 HTTPS 수신 주소, AES-256-GCM 복호화, challenge 검증, 비밀키 교체 절차를 문서대로 구현한다.
- data.id로 중복 제거하고 occurredAt으로 오래된 상태가 최신 상태를 덮지 못하게 한다.
- 일반 전달은 최초+재시도 1회이며 재시도는 약 1분 뒤 예정된다. 작업 복구에 따라 추가 중복도 발생할 수 있다. 순서는 보장되지 않는다.
- 내구성 있는 저장 이후 2xx 응답, 후속 처리는 비동기. 408/429/5xx·연결 실패는 남은 시도 내 재시도 대상이다.
- Webhook만으로 누락 복구를 보장하지 않는다. 상태와 실적을 주기 조회해 대조한다. 조회 주기는 호출 제한 확인 후 결정한다.
- SDK/문서 존재는 보유 L4 펌웨어·계정에서 모든 필드가 실제 제공된다는 보장이 아니다.

## 8. PUDU 및 BIB 현황

PUDU 공식 진입점: https://open.pudutech.com/en 및 https://open.pudutech.com/en/cloud-api
플랫폼 차원의 작업·상태·콜백 Cloud API 안내를 확인했다. MT1·CC1·BG1별 정확한 API 지원표·인증·필드·명령 규격은 아직 확보/검증하지 않았다. 본체 매뉴얼 기능을 외부 API 지원으로 판단하지 않는다. BG1이나 CC1을 유사 모델과 혼동하지 않는다.
BIB J40은 사용자가 추후 검토하기로 결정했다. 현재 외부 API 문서 확인 또는 연결을 개발 선행 조건으로 삼지 않는다.

## 9. 개발 단계와 완료 기준

1. 시제품: 7개 화면, 총 20대 가상 데이터, 역할별 사용 흐름, 지도 영역 선택 시뮬레이션, 보고서 초안·확정·출력. 실제 브랜드별 지원을 가정한 동작에는 시뮬레이션 표시.
2. 기반: 서버 인증·사업장별 인가·영속 저장·감사 이력·환경 분리. UI에서 숨기는 것만으로 권한 구현 완료 처리 금지.
3. CenoBots 읽기: 한 대의 인증·상태·지도·실적 조회를 본체/제조사 보고서와 대조.
4. CenoBots 제어: 지정 시험 로봇과 시험 시간에 시작·일시정지·재개·중단·복귀·예약·구역 청소 확인. 실기 제어 시험 시점과 대상은 별도로 정한다.
5. 이벤트·알림·보고서: 중복·역순·누락·복구 테스트, 이메일/알림톡 연결, 확정 보고서 버전 유지.
6. PUDU 확장 및 5개 사업장 시범 운영. BIB는 후속 단계.

필수 테스트:
- 다른 사업장 로봇·지도·보고서 파일 직접 접근 차단.
- 고객 기본 계정의 명령 API 호출 차단, 추가 권한의 범위 검증.
- 같은 버튼 중복 클릭과 본사/고객 동시 명령 충돌.
- API 응답 유실·통신 끊김·인증 실패 시 허위 성공 표시 없음.
- 지도 버전 불일치·범위 밖 다각형·좌표 미제공 시 영역 명령 차단.
- Webhook 중복·역순·복호화 실패·서버 재시작 후 처리.
- 중복 실적·늦은 실적·분모 0·미수신·월 경계의 보고서 계산.
- 로봇 사업장 이동 후 이전 실적의 소속 유지.
- 확정 보고서가 재집계로 변경되지 않음.

## 10. 기술·운영 선택 시 원칙

5개 사업장·20대 규모에 맞는 단순한 서버 구조를 먼저 제안한다. 제조사별 모듈 분리를 위해 서비스 전체를 과도하게 분산할 필요는 없다. 기술 스택과 호스팅은 확정되지 않았으므로 Claude가 비용·배포·유지관리 관점에서 근거를 제시하고 선택한다. 최신 가격은 조회 없이 단정하지 않는다.
앱 서버/DB/백그라운드 수집·예약 작업/PDF 저장/알림 모듈의 책임을 구분한다. 실제 클라우드 구매·유료 발송·배포는 아직 수행하지 않았다.
코드 버전 관리, 환경변수 예시, DB 변경 이력, 실행/배포 설명, 백업·복구 절차, 운영 장애 감시, 키 교체를 포함한다. 비밀값과 고객 실제 자료를 샘플 데이터에 넣지 않는다.

## 11. 남은 입력 — 초기 시제품을 막지 않음

- 실제 사업장명, 모델별 대수, 층·구역·로봇 배치.
- CenoBots 실제 서버 지역·키 권한·호출 제한·지원 펌웨어. 키는 안전한 서버 설정에서 입력.
- PUDU 상세 개발 문서 및 테스트 접근.
- 클라우드 예산·운영 담당자·보관기간·백업 목표.
- 알림 채널 공급사, 수신자·발신 설정, 고객 공개 범위 세부.
- 로고·시각 디자인·보고서 최종 양식.

각 개발 단계 종료 시 구현 항목, 실행 방법, 테스트 근거, 남은 제한, 다음 단계만 간결히 보고한다. 실제로 실행하지 않은 시험을 통과했다고 쓰지 않는다.
