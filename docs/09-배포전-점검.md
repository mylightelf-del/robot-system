# 09. 배포 전 점검 (사전 준비 작업과 체크리스트)

사용자 요청(2026-10-29): "서버 배포하기 전 하면 좋은 게 있다면 해보자". 외부 계정 없이 할 수 있는 것을 먼저 했다. Docker 데몬이 이 작업 환경에 없어 이미지 빌드 자체는 실서버에서 처음 확인한다.

## 1. 이번에 추가한 것

## 2. 점검한 것(이상 없음)
- `.dockerignore` 가 `.env*`(예시 제외)·`.git`·`node_modules`·백업을 제외해 이미지에 비밀값이 들어가지 않는다.
- 웹 이미지는 standalone 최소 런타임, 비루트 사용자, 헬스체크 포함. 워커 이미지는 tsx 로 실행하며 같은 비루트 사용자.
- 웹은 127.0.0.1:3000 에만 바인딩하고 Caddy 가 80/443 을 맡는다. Cloudflare 는 Full (strict).
- 세션 쿠키는 운영(APP_ENV=production)에서 secure, httpOnly, sameSite=lax. 로그인 잠금(5회/15분). 샘플 초기화는 운영에서 꺼진다.
- `/api/webhooks/*` 만 세션 없이 열려 있고 CallbackCode 로 검증한다. `/api/maps/*` 는 세션 + 사업장 권한. `/api/health` 는 공개지만 DB up/down·워커 상태·시각만 준다.
- PUDU 키는 서버 환경변수에만 있고 trace_id 의 키 접두사는 저장 전에 제거한다. 로그에 키가 찍히는 곳이 없다(`client.describe` 는 앞 3자만).
- 백업 스크립트(`scripts/backup.sh`, 14일 보관, 선택 S3 업로드)는 지도 이미지(DB 보관)까지 포함한다.

## 3. 배포 당일 체크리스트
1. `.env` 작성: `APP_ENV=production`, `APP_BASE_URL=https://widebot.kro.kr`, `DOMAIN=widebot.kro.kr`, `ACME_EMAIL`, `POSTGRES_PASSWORD`(긴 난수), `ALLOW_SAMPLE_RESET=false`, `SAMPLE_USER_PASSWORD` 없음, `VENDOR_MODE=live`, `PUDU_API_CLUSTER=sea`, **새로 발급한** `PUDU_API_APP_KEY/SECRET`, `PUDU_SHOP_IDS`(4곳), `PUDU_CALLBACK_CODE` 는 콜백 등록 뒤.
2. `docker compose up -d --build` → migrate 단계 로그에서 "마이그레이션 적용 완료" 와 preflight "오류 0" 확인. 오류면 web/worker 가 뜨지 않으므로 `.env` 를 고치고 `docker compose up -d`.
3. `curl https://<도메인>/api/health` → `{"ok":true,"db":"up","worker":"up"}`. worker 가 unknown/stale 이면 `docker compose logs worker`.
4. 첫 관리자: `docker compose run --rm worker npx tsx scripts/bootstrap-admin.ts "이름" admin@회사` → 초대 링크로 비밀번호 설정 → 로그인.
5. 관리 설정: 사업장·층 생성 → PUDU 패널 『연결 확인 + 로봇 조회』 → 로봇 등록·배치 → 『PUDU 지도 가져오기』 → 로봇 화면에서 상태·위치 확인.
6. 콜백: `docs/05` 3-3-2 절차로 대리점에 등록 요청 → `PUDU_CALLBACK_CODE` 입력·재기동 → 『콜백 URL 자가 점검』.
7. 외부 감시 등록(`/api/health`, 5분 간격, `"worker":"up"` 문자열 포함 조건), 백업 cron 등록(`docs/05` 3-1).
8. 샘플 데이터는 운영 DB 에 넣지 않는다(preflight 가 경고).

## 4. 아직 못 한 것
- Docker 이미지 빌드·compose 기동은 실서버에서 처음 확인한다(이 환경에 Docker 없음).
- 알림 발송(이메일/SMS)은 모의 발송 상태라 운영에서도 실제로 보내지 않는다(별도 단계).

## 6. 서버 생성 (2026-10-29)
- 시드니(ap-southeast-2a)에 Lightsail `widebot-web`(Small 2GB, Ubuntu 24.04), 고정 IP 54.79.35.154, 방화벽 22/80/443, 자동 스냅샷 켬. 첫 부팅 스크립트로 Docker·2GB 스왑·작업 폴더를 준비했다. 세부는 `docs/05` 2-1.
- 플랜 검토: 평상시 1.0~1.3GB, 빌드 시 2GB 이상 필요 → Micro(1GB)는 제외, Small(2GB)+스왑으로 시작, 부족하면 Medium(4GB, 월 24달러)으로 스냅샷 승급.
- 원격 작업 채널: 사용자가 SSH 를 직접 다루기 어려워 인스턴스를 다시 만들며 첫 부팅 스크립트로 SSM 에이전트를 하이브리드 활성화(`mi-0d6dbe7bc429007bf`)했다. 이후 모든 서버 작업은 Run Command 로 한다(`scripts/deploy-remote.sh`). SSM 기본 셸이 dash 라 스크립트는 `bash -c` 로 감싼다.
- DNS: 사용자가 내도메인.한국에서 A 레코드를 54.79.35.154 로 설정 완료(조회 확인).

## 5. 도메인 확정 (2026-10-29)
- 사용자가 `widebot.kro.kr`(내도메인.한국 무료 서브도메인)을 확보했다. 조회 결과 아직 A 레코드가 없다(NXDOMAIN) — Lightsail 고정 IP 가 나오면 입력한다.
