# 17. 다른 로봇 통합관제 시스템과의 비교 · 개선 제안 (2026-11-07)

사용자 요청: "다른 로봇통합관제 시스템과 비교해서 어떤 부분이 다른지 검토하고, 어떤 부분을 개선하면 좋을지 리스트를 만들어줘."

## 0. 비교 대상과 자료의 한계
| 구분 | 대상 | 자료 |
|---|---|---|
| 제조사 클라우드(청소 로봇) | PUDU Link(푸두), Gausium Cloud(가우시움), BrainOS Fleet Ops(브레인코프·테넌트), Avidbots Command Center, Nilfisk TrackClean | 제조사 홈페이지·보도자료·판매점 설명 |
| 이기종 통합 플랫폼 | InOrbit, Formant, Open-RMF(오픈소스), 카카오모빌리티 브링온, 클로봇 CROMS, 현대로보틱스 Narchon | 보도자료·블로그 |

- 대부분 **업체가 스스로 낸 자료**다. 실제 화면을 써 본 것이 아니고, 요금·계약 등급에 따라 되는 기능이 다를 수 있다. 수치(예: "원격으로 장애 70% 해결", "가동률 8배")는 업체 주장이다.
- 이 시스템은 코드와 운영 화면을 직접 보고 적었다(`docs/01~16`).

## 1. 성격이 다른 점 — 먼저 알아 둘 것
- **제조사 클라우드**(PUDU Link 등)는 *그 회사 로봇만* 다루고, 로봇을 가장 깊게 안다(원격 진단, 지도 편집, 예약 생성·수정이 모두 됨). 이 시스템은 그 위에서 **여러 제조사·여러 사업장·여러 고객사**를 한 화면으로 묶고, 고객에게 보여 줄 것과 아닐 것을 가르고, 보고서를 만드는 **운영사(포스코와이드) 관점의 계층**이다. 제조사 앱을 대체하는 것이 아니라 그 위에 얹는 것이다.
- **이기종 통합 플랫폼**(브링온·InOrbit·Open-RMF)은 배송·안내 로봇까지 포함해 **배차·교통 제어·엘리베이터 연동**이 핵심이다. 청소 로봇은 정해진 경로를 혼자 돌기 때문에 이 기능의 필요가 작다. 지금 단계에서 따라갈 항목이 아니다.

## 3. 개선 제안 목록 (우선순위 순)
난이도: 하(며칠) · 중(1~2주) · 상(그 이상). "PUDU 확인"은 API 가 그 데이터를 주는지 문서·실기로 확인한 뒤에만 진행한다(추측 구현 금지).

### A. 바로 할 만한 것 — 운영 효과 크고 난이도 낮음
1. **보고서 자동 이메일 발송** — 주간·월간 보고서가 확정되면(또는 초안이 만들어지면 본사에) 수신자에게 PDF/PPT 첨부 또는 링크를 자동 발송. 타사 공통 기능. 전제: SES 프로덕션 접근(지금은 샌드박스라 검증된 주소만 가능). 난이도 하.
2. **예정 작업 미실행 알림** — 계획 회차가 '미실행'으로 확정되면 현장 담당자에게 알림, 그리고 "N시간/일 동안 청소 실적이 없는 로봇" 알림(Avidbots 의 subscription alert 와 같음). 지금은 장애만 알린다. 난이도 하.
3. **KPI 보강(대시보드·보고서)** — 생산성(m²/시간), 로봇별 가동 시간, 완료율 추이(전주·전월 대비 ±), 장애 평균 조치 시간, 미조치 비율, 사업장 간 비교. 데이터는 이미 있다. 난이도 하~중.
4. **대시보드 '오늘 할 일' 묶음** — 미실행 회차·미조치 장애·소모품 임계·상태 미수신 로봇을 한 카드로. 난이도 하.
5. **모바일 사용성 점검 + 홈 화면 추가(PWA)** — 전용 앱 대신 현장 담당자가 폰에서 바로 열고 알림은 카카오톡으로 받는 구조를 다듬는다. 난이도 하~중.
6. **사용자별 알림 구독** — 알림 종류(장애/미실행/보고서)·사업장·채널별 켜고 끄기, 야간 금지 시간. 지금은 사업장별 수신자 목록만. 난이도 중.

### B. 다음 단계 — 타사와의 체감 차이를 줄이는 것
7. **청소 범위 증빙(커버리지 지도)** — 실적마다 청소한 구역·궤적을 지도에 표시, 놓친 구역 강조, 기간 히트맵. **PUDU 확인**: 보고서 API 에 궤적/커버리지 맵(이미지 또는 좌표)이 있는지. 있으면 설치·주간·월간 보고서에 넣는다. 난이도 중~상.
8. **화면에서 예약 만들기·바꾸기** — **PUDU 확인**: 예약 쓰기 API 유무. 없으면 "이 시스템의 계획"으로만 관리하고 PUDU 예약과 대조해 차이를 표시. 난이도 중.
9. **장애 조치 가이드·반복 장애 분석** — 장애 코드별 권장 조치(현장에서 할 수 있는 것/제조사 호출), 로봇별·코드별 반복 횟수 Top N, 재발 간격. 가우시움의 '원격 정비' 를 대신해 현장이 스스로 해결하게 한다. 난이도 중.
10. **소모품·정비 예측** — 사용량 기반 교체 예정일, 점검 항목의 주기 알림(점검 기능은 있으나 알림과 연결되지 않음). 난이도 중.
11. **읽기 전용 오픈 API·웹훅** — 고객사 시설관리/BMS 가 실적·장애를 가져가게 토큰 발급(사업장 범위·감사 기록 적용). 엑셀 수동 전달을 줄인다. 난이도 중.
12. **장애 조치에 사진 첨부** — 보고서 사진 기능을 재사용. 난이도 하.

### C. 장기 — 사업 범위가 넓어질 때
13. **다른 제조사 실연동**(CenoBots·가우시움·BIB) — 어댑터 구조는 준비됨, 실제 키·문서가 오면 진행. 난이도 상.
14. **실시간 콜백** — PUDU `callback_code` 를 받으면 상태 지연이 60초 → 수 초. 코드 변경은 끝나 있음(대리점 대기).
15. **ROI 보고서** — 시급·수작업 생산성을 입력받아 인건비 환산, 자율 가동률(로봇이 혼자 돈 시간 비율). 타사 영업 자료의 핵심 지표. **PUDU 확인**: 수동/자율 구분 데이터 유무. 난이도 중.
16. **엘리베이터·자동문 연동** — 다층 자율 이동이 필요한 사업장이 생길 때. 제조사 IoT 모듈이나 브링온 같은 플랫폼을 통해. 난이도 상.
17. **다국어·시간대 라이브러리** — 해외 현장이 생길 때(`docs/14` 제안). 난이도 중.

## 4. 이 시스템이 이미 앞서 있는 것(지키면 되는 것)
- 고객·현장·본사 역할 분리와 **서버 쪽 사업장 범위 검사**, 고객에게 원시 오류·내부 메모·초안 비노출.
- 보고서 **수치 보정(원본 보존)·확정·버전**, 설치 완료보고서(지도·사진·주간 타임라인), PPT·Excel.
- 장애 **워크플로**(확인·담당·조치·복구·되돌리기·알림 삭제·미조치 확대 통보).
- **안전장치**: 로봇 자체 지도를 절대 바꾸지 않음, 사업장별 원격 제어 스위치, 상태 신선도·중복 시작 방지, 사유 필수·감사 기록, 사용 중지로 이력 보존.
- 운영: 백업·이력 적재·멱등 스크립트, 비밀값 서버 전용.
