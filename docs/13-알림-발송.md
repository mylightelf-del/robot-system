# 13. 알림 실제 발송 — 이메일(AWS SES)·카카오톡 (2026-10-31)

사용자 요청: "알림 이메일 발송과 카톡 알림 전달까지 해보자".

## 1. 무엇을 보내나
| 언제 | 대상 | 비고 |
|---|---|---|
| 장애 발생 | 사업장 수신자(등급·시간대 조건) | PUDU 장애 로그 폴링(10분)으로 받은 것 중 **발생 60분 안**의 등급 HIGH 이상(`NOTIFY_FRESH_MINUTES`). 콜백 등록 뒤에는 콜백으로도 |
| 장애 복구 | 같은 수신자 | 장애·조치 화면의 '복구' |
| 미조치 확대 통보 | 같은 수신자 | 발생·확인 상태로 사업장 설정 시간(기본 60분)을 넘기면 **한 번**. 최근 24시간 안의 장애만(배포 직후 몰아서 보내지 않게) |
| 시험 발송 | 본인 / 지정 수신자 | 내 계정 → 알림 받기, 관리 설정 → 알림 수신 설정의 '시험 발송' |

같은 장애의 반복 발생은 묶음 처리라 다시 보내지 않고, '중복 억제' 분 안의 같은 장애도 억제한다. 발송 결과는 장애 건의 알림 기록에 **발송 / 모의 / 억제 / 실패**로 남는다.

## 2. 이메일 — AWS SES (시드니 ap-southeast-2)
- 서버 설정: `MAIL_MODE=live`, `MAIL_FROM`, `SES_ACCESS_KEY_ID/SES_SECRET_ACCESS_KEY`(발송 전용 IAM 사용자 `widebot-ses-sender`, 정책 `ses:SendEmail/SendRawEmail` 만, 보내는 주소는 `*@widebot.kro.kr` 와 `mylightelf@gmail.com` 만 허용).
- SES 신원: 도메인 `widebot.kro.kr`(Easy DKIM, 확인 대기), 이메일 `mylightelf@gmail.com`(확인 메일 발송됨).
- **샌드박스 상태**: 확인된 주소로만 보낼 수 있고 하루 200통·초당 1통. 고객사·현장 담당자 주소로 보내려면 **SES 프로덕션 접근 신청**(도메인 확인 뒤 권장)이 필요하다.
- 보내는 주소: 도메인 확인 전에는 `청소로봇 관제 <mylightelf@gmail.com>` 로 보낸다(gmail.com DMARC 는 p=none 이라 거부되지는 않지만 스팸함에 갈 수 있다). 도메인이 확인되면 `noreply@widebot.kro.kr` 로 바꾼다.

## 3. 카카오톡 — "나에게 보내기"
- 공식 문서(카카오 로그인·메시지 REST API, 2026-10-30 확인)대로 구현: 인가 → 토큰(`client_secret` 포함) → `access_token_info` 로 회원번호 → `POST /v2/api/talk/memo/default/send`(text 템플릿, 200자, 링크 버튼 '관제 화면 열기').
- **받는 사람마다 본인이 연결**한다: 내 계정 → 알림 받기 → 『카카오톡 연결』(카카오 로그인, 동의 항목 '카카오톡 메시지 전송'). 관리자는 알림 수신 설정에서 수신자로 '카카오톡(사용자 본인)' 을 고른다. 메시지는 그 사람의 카카오톡 '나와의 채팅'에 온다.
- 토큰은 DB 에 AES-256-GCM 으로 암호화해 둔다(`TOKEN_ENCRYPTION_KEY`, 서버 .env). 액세스 토큰은 만료 5분 전·401 이면 갱신, 리프레시 토큰은 하루 1회 점검해 남은 기간 35일 미만이면 갱신(카카오는 1개월 미만일 때 새 리프레시 토큰을 준다) → 알림이 드물어도 연결이 유지된다.
- 한계: 이 방식은 **연결한 본인에게만** 보낼 수 있다(다른 사람에게 보내기는 카카오 별도 권한). 고객사 담당자·다수에게 전화번호로 보내는 **알림톡**은 카카오톡 채널 + 사업자 인증 + 발송대행사(솔라피·NHN Cloud 등) + 템플릿 검수가 필요해 다음 단계로 둔다(수신자 '전화번호'는 지금 모의 발송).
- 카카오 앱 설정(사용자가 developers.kakao.com 에서): 앱 만들기 → 카카오 로그인 사용 ON → 리다이렉트 URI `https://widebot.kro.kr/api/kakao/callback` → 동의 항목 '카카오톡 메시지 전송(talk_message)' 선택 동의 → 플랫폼(제품 링크 관리) 웹 도메인 `https://widebot.kro.kr` → 앱 키의 REST API 키와 클라이언트 시크릿을 서버 `.env` 의 `KAKAO_REST_API_KEY`, `KAKAO_CLIENT_SECRET` 에.

## 4. 시험
- `tests/notify.test.ts`(5): 토큰 암호화 왕복·위조·다른 키 거부, 이메일 모의/발송/공급사 오류(HTML 이스케이프), 카카오 연결(잘못된 코드 거부·암호화 저장) → 나에게 보내기(200자·링크) → 401 갱신 후 재시도 → 연결 유지 갱신(새 리프레시 토큰), 미연결·전화번호 수신 처리, 수신자 검증, 장애 발생 → 카카오 실제 발송, 확대 통보 1회·24시간 한정·등급 미달 억제. 카카오는 공식 문서의 경로·파라미터를 흉내 낸 모의 서버로 시험했다.
- `tests/pudu.test.ts`: 폴링으로 받은 최근 장애만 알림, 오래된 것은 보내지 않음. `tests/ops.test.ts`: 알림 설정 점검.
- 브라우저: 내 계정 → 이메일 시험 발송(모의 기록), 카카오 연결 버튼 → 카카오 인가 주소로 이동(파라미터 확인), 관리 설정 → 카카오톡 수신자 추가·시험 발송(미연결 사유 표시).
- **실제 SES·카카오 발송은 운영 서버에서 확인 메일 클릭·카카오 앱 키 입력 뒤에 확인한다.**
