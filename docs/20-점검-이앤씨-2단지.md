# 20. 점검 — 포스코이앤씨 단기 '2단지 1번' 데이터 (2026-11-08)

사용자 보고: "2단지 1번 데이터가 정상적으로 안 들어오고 있어."

## 1. 확인한 사실
- 실적(청소 보고서)은 정상적으로 들어오고 있었다. 10-28~11-06 매일 21:00 작업이 COMPLETED 로 적재됐고 수신 지연도 0시간이다.
- 문제는 **화면에 보이는 두 가지**였다.
  1. **계획 완료율**: 10-31·11-01·11-03·11-04 회차가 실적이 있는데도 '미실행'으로 남아 있었다. 원인: '미실행 재연결'(늦게 온 실적과 다시 맞추기, `docs/14`)이 11-07 새벽에 배포돼 그 전에 판정된 회차는 48시간 창 밖이라 영영 미실행이었다.
  2. **로봇 상태**: 11-07 21:00 작업이 4시간 넘게 돌고 있는데(실기 조회: 작업 코드 302 청소 중, 배터리 76→63%) 화면은 '대기'였고, 00:00 에 '예정 작업 미실행' 통보가 나갔다(오판).
- 상태 오표시의 원인(콜백 적용 뒤 생긴 새 문제): 콜백(`notifyRobotStatus`)은 run_state(BUSY/IDLE)만 주고 작업 코드가 없다. 콜백이 상태의 '데이터 시각'을 계속 앞당기자, 상세 폴링(작업 코드·진행률)이 **역순 방어에 걸려 전부 거부**됐다(워커 로그 `갱신 2/6`). 그래서 BUSY 로봇이 '대기'로 남았고, 미실행 판정도 '대기'를 보고 내려졌다.

## 2. 고친 것(배포 2026-11-07 15:38 UTC)
| 문제 | 수정 |
|---|---|
| 콜백 뒤 상세 폴링 거부 | 역순 방어는 폴링끼리만 비교(마지막 기록이 콜백이면 비교 안 함). 배포 뒤 `갱신 6/6` 확인 |
| BUSY 콜백이 '대기' | run_state=BUSY → 작업 중(기존 청소·일시정지·복귀·오류는 유지), IDLE 콜백은 오류 상태를 지우지 않음. 상세 폴링이 60초 안에 코드로 보정 |
| 작업 중인데 미실행 판정 | 로봇이 작업 중(상태 15분 안 갱신)이면 판정을 미룸 |
| 48시간 지나면 영영 미실행 | 재연결 기간 14일. 배포 직후 2단지 1번 10-31~11-07 전부 DONE 으로 바뀜 |
| 같은 시각 중복 예약(포스코센터 2층 22:00 ×2) | 한 건이 수행되면 다른 건은 EXCLUDED(완료율 분모 제외) |

## 3. 남은 것
- 이미 나간 11-07 '예정 작업 미실행' 통보(2단지 1번)는 오판이었다. 수신자에게 안내 필요.
- 2단지 1번의 LostLocalization 장애 2건(10-25, 10-29)이 아직 미조치(OPEN)로 남아 있다. 복구됐으면 장애 화면에서 복구 처리.
- 콜백은 정상 수신 중(12시간 동안 상태 392 · 온라인/오프라인 86 · 예약 작업 8건). `docs/18` 4장의 "실제 수신 확인 대기"는 해소.
