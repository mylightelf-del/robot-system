# 14. 전체 점검 · 고급 설정 분리 · 올해 데이터 (2026-10-31)

사용자 요청: ① 사업장·층·구역·로봇 배치와 제조사 연결(PUDU)을 별도 고급 설정으로 ② 로봇의 층(지도)을 바꾸지 말 것 ③ 올해 데이터 모두 받기 ④ 전체 점검·개선 검토.

## 1. 로봇 지도·층에 대해 확인한 사실
- 이 시스템이 PUDU 에 보내는 '바꾸는' 호출은 **작업 명령(`task/exec`: 시작·일시정지·재개·중지·복귀) 하나뿐**이다. 로봇의 지도·층을 바꾸는 API 는 코드에 없다. 지도 관련 호출은 목록·상세 **읽기**만 한다(독립 검토로도 확인).
- '층 지도 맞추기'·'PUDU 지도 가져오기'·'로봇 배치 변경'은 **이 시스템 DB 안의** 층 지도·구역·배치만 바꾼다. 지금까지 운영에서 로봇 배치(층)를 바꾼 적은 없다(초기 구성 때 배치만).

## 2. 고급 설정 분리 · 안전장치
- `관리 설정` 에서 '사업장·층·구역·로봇 배치', '제조사 연결 — PUDU', '제조사 연결 목록'을 **`/admin/advanced`(고급 설정)** 로 옮겼다. 들어가면 '이해했습니다' 체크 전에는 화면이 잠겨 있다(눌러도 동작 안 함).
- 층 지도 맞추기: **비교(미리 보기) → 층을 골라 적용** 두 단계. 미리 보기는 아무것도 바꾸지 않는다.
- PUDU 지도 가져오기: 바꾸기 전 확인 창(로봇 자체 지도는 그대로, 이 시스템 기준만 바뀜).
- 실제 로봇의 배치(층) 변경: **사유 필수**, 감사 기록에 남김. 같은 층으로의 이동은 거부.

## 3. 올해 데이터
- 실기 확인: PUDU 문서의 '최근 180일'과 달리 4월 구간(4/10~17)도 응답했다(포스코센터 보고서 34건·장애 13건). 1~3월은 0건(설치 전으로 보임).
- `scripts/pudu-backfill.ts --from 2026-01-01` 로 올해 전체를 받는다(멱등 — 이미 있는 것은 건너뜀). 배포 뒤 서버에서 실행.

## 4. 점검 결과와 조치
독립 검토(코드 읽기) + 직접 확인. **조치함**:
| 문제 | 영향 | 조치 |
|---|---|---|
| 상태가 오래된 로봇에도 명령 전송 가능 | 폴링이 멈췄을 때 실제와 다른 상태로 시작 명령 | 실제 로봇은 상태가 5분 넘게 갱신되지 않았으면 명령 거부 |
| 시작·재개 명령이 실행 확인 전에 두 번 갈 수 있음 | 동시 시작·결과 불명 직후 재전송 | 실행 확인 전(요청·접수)·결과 불명인 시작 계열이 있으면 거부 |
| 미조치 확대 통보가 '억제' 기록을 5분마다 쌓음 | 장애당 최대 288행 | 억제 기록에도 통보 종류를 붙여 한 번만 |
| 고객 화면 * 표시에 '원래 집계값' 노출 | 보정 전 값이 고객에게 보임 | 고객에게는 '담당자 보정'만 |
| 긴 작업의 계획 회차가 '미실행'으로 굳음 | 완료율 과소 | 48시간 안에 늦게 온 실적과 다시 맞춤 |
| PUDU 에서 지운 예약이 계속 회차를 만듦 | 가짜 미실행 | 동기화 때 사라진 예약은 사용 중지 |
| 화면에서 PUDU 예약을 켜고 꺼도 다음 동기화에 되돌아감 | 혼동 | PUDU 예약은 'PUDU 앱에서 변경' 표시, 서버도 거부 |
| 이력 적재한 기간 보고서의 '운영 대수 0대' | 숫자 오류 | 기간 실적이 있는 로봇도 셈 |
| PUDU 실적엔 구역 정보가 없는데 구역 표가 전부 0 | 오해 | 구역 정보가 없으면 표를 빼고 주석 |
| 카카오 수신자가 비활성화·권한 회수 뒤에도 받음 | 정보 노출 | 보낼 때마다 활성·사업장 권한 확인 |
| 장애 저장 전에 알림 발송 | 저장 실패 시 다음 주기 중복 알림 | 저장 후 알림 |
| 재집계 뒤 보정의 '원래 집계' 기록이 낡음 | 엑셀 보정 내역 오류 | 재집계 때 원래값 갱신 |
| 고객에게 장애 코드·제조사 원문 오류 노출 | 원칙 위반 | 고객 화면에서 코드 숨김, 명령 결과는 요약 문구 |
| 장애 '복구' 처리 시 실제 로봇 상태를 '대기'로 덮음 | 실제 오류가 가려질 수 있음 | 샘플 로봇에만 적용 |
| 린트 오류 2건(따옴표) | — | 수정 |

**제안(결정 필요)**:
- 실제 로봇 원격 명령 전체 스위치(`PUDU_COMMANDS_ENABLED`, 기본 꺼짐): 지금은 현장 담당자·제어 권한 고객이 화면에서 실제 로봇에 시작·중지·복귀를 보낼 수 있다. 기종별 명령 시험을 미뤄 둔 상태라 켜 둘지 정해야 한다.
- 이동한 로봇의 과거 실적 층 표시(실적은 당시 사업장으로 가지만 층은 현재 층으로 기록) — 로봇을 옮길 일이 생기면 함께 고친다.
- 사업장 시간대는 한국(Asia/Seoul)만 정확하다(고정 오프셋). 해외 현장이 생기면 시간대 라이브러리로 바꾼다.

## 5. 시험
- 전체 90개 통과: 고급 설정과 별개로 추가한 시험 — 층 지도 미리 보기는 변경 없음·고른 층만 적용·로봇 배치 그대로·로봇 명령 0회, 실제 로봇 배치 변경 사유 필수, 오래된 상태 명령 거부·시작 중복 거부, PUDU 지운 예약 사용 중지·PUDU 예약 토글 거부, 늦게 온 실적 재연결, 억제 확대 통보 1회.
- 브라우저: 관리 설정 카드(운영·사용자·고급 설정 링크·알림·감사), 고급 설정 잠금(체크 전 클릭 안 됨 → 체크 후 해제).
