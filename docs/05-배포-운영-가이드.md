# 05. 배포·운영 가이드 — AWS Lightsail + Docker Compose + Cloudflare

대상: 운영 담당자(프로그래밍 초보 가정). 명령은 순서대로 복사해 실행한다. 비밀값은 서버의 `.env` 에만 둔다.
가격·화면 명칭은 변동될 수 있으므로 AWS·Cloudflare 콘솔의 현재 표기를 따른다.

## 1. 구성 요약
```
사용자 ──HTTPS──▶ Cloudflare(DNS·방화벽·DDoS) ──HTTPS──▶ Lightsail VM
                                                     ├─ caddy  (HTTPS 종단, 80/443)
                                                     ├─ web    (Next.js, 127.0.0.1:3000)
                                                     ├─ worker (시뮬레이션/수집/예약/세션 정리)
                                                     └─ db     (PostgreSQL 16, 볼륨 pgdata)
```
- 모든 구성은 `docker-compose.yml` 한 파일. 로컬에서도 같은 파일로 띄울 수 있다.
- `docker compose up` 시 migrate 서비스가 DB 마이그레이션을 먼저 적용한 뒤 web·worker 가 뜬다.

## 2. 최초 설치 (약 30분)

### 2-1. Lightsail 인스턴스
1. AWS 콘솔 → Lightsail → 인스턴스 생성. 리전 **서울(ap-northeast-2)**, 플랫폼 Linux, 블루프린트 **OS 전용 → Ubuntu 24.04**.
2. 플랜: 2GB RAM 이상(웹+워커+DB 를 한 대에서 돌리므로). 처음엔 2GB 로 시작하고 모자라면 올린다.
3. 생성 후 **고정 IP** 를 만들어 연결한다(재시작해도 IP 유지).
4. 네트워킹 → 방화벽: SSH(22), HTTP(80), HTTPS(443) 만 허용. 22 는 가능하면 본인 IP 로 제한.
5. 스냅샷 → **자동 스냅샷 켜기**(일 1회). 이것이 서버 전체 백업이다.

### 2-2. 서버 준비 (SSH 접속 후)
```bash
sudo apt-get update && sudo apt-get install -y ca-certificates curl git
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER && newgrp docker
sudo mkdir -p /opt/robot-system && sudo chown $USER /opt/robot-system
git clone <저장소 주소> /opt/robot-system
cd /opt/robot-system
cp .env.example .env
```
`.env` 를 열어 최소한 다음을 바꾼다.
```
APP_ENV=production
APP_BASE_URL=https://widebot.kro.kr        # 실제 도메인(2026-10-29 사용자 확보: widebot.kro.kr)
DOMAIN=widebot.kro.kr
ACME_EMAIL=<운영 담당 이메일>                # 인증서 발급기관(Let's Encrypt/ZeroSSL) 계정·만료 알림용
POSTGRES_PASSWORD=<긴 무작위 문자열>         # 예: openssl rand -base64 24
ALLOW_SAMPLE_RESET=false
SAMPLE_USER_PASSWORD=                       # 운영에서는 비움(샘플 사용자 미적재)
VENDOR_MODE=live                            # PUDU 실제 연동(키·클러스터·허용 매장은 아래 3-3-1)
```
> DATABASE_URL 은 docker-compose 가 POSTGRES_* 로 만들어 주므로 .env 에 적지 않아도 된다.

### 2-3. 도메인 연결 — `widebot.kro.kr` (내도메인.한국 무료 도메인)
확인 결과(2026-10-29) `kro.kr` 은 Public Suffix List 에 없는 무료 서브도메인 서비스라 **Cloudflare 에 사이트로 추가할 수 없다**(Cloudflare 는 등록 가능한 도메인만 받음). 그래서 Cloudflare 없이 서버의 Caddy 가 직접 HTTPS 를 맡는다. 보안 헤더·HTTPS 는 Caddy 가 처리하고, WAF·DDoS 완충은 없다(라이트한 내부용 운영에는 충분. 나중에 정식 도메인(.kr/.com, 연 1~2만원)을 사면 아래 '정식 도메인일 때' 절차로 Cloudflare 를 붙일 수 있다).
1. 내도메인.한국(xn--220b31d95hq8o.com) 로그인 → 내 도메인 `widebot.kro.kr` 관리 → **A 레코드**(IP 연결)에 Lightsail **고정 IP** 입력 → 저장. (CNAME·네임서버 설정은 쓰지 않는다.)
2. 1~10분 뒤 확인: `nslookup widebot.kro.kr` 이 고정 IP 를 돌려주면 된다.
3. `.env` 의 `DOMAIN=widebot.kro.kr`, `APP_BASE_URL=https://widebot.kro.kr`, `ACME_EMAIL=<이메일>` 을 확인하고 `docker compose up -d`. Caddy 가 80/443 으로 인증서를 자동 발급한다(Lightsail 방화벽에 80·443 이 열려 있어야 함).
4. 인증서 주의: Let's Encrypt 는 '등록 도메인당 주 50건' 한도를 `kro.kr` 전체 사용자와 나눠 쓴다. 발급이 거절되면 Caddy 가 ZeroSSL 로 자동 재시도한다(`deploy/Caddyfile`). `docker compose logs caddy` 에서 "certificate obtained" 를 확인한다. 발급 직후에는 몇 분 걸릴 수 있다.
5. 확인: `curl -s https://widebot.kro.kr/api/health`.

**정식 도메인일 때(선택, Cloudflare 사용)**
1. Cloudflare 에 도메인 추가(무료 플랜) → 네임서버를 등록기관에서 Cloudflare 로 변경.
2. DNS → A 레코드: 호스트 → Lightsail 고정 IP, **프록시 켬(주황 구름)**.
3. SSL/TLS → 암호화 모드 **Full (strict)**. (서버의 Caddy 가 정식 인증서를 발급하므로 strict 가능)
4. 보안 → WAF: 관리형 규칙 기본값 켬. 원하면 국가 제한(한국 외 차단)도 가능하다.

### 2-4. 기동
```bash
cd /opt/robot-system
docker compose up -d --build
docker compose ps                 # 4개 모두 Up 인지
docker compose logs migrate       # "마이그레이션 적용 완료" 와 배포 전 점검 "오류 0" 확인(오류면 web/worker 가 뜨지 않음 → .env 수정 후 up -d)
docker compose logs -f web        # "Ready" 확인 후 Ctrl+C
curl -s https://widebot.kro.kr/api/health   # {"ok":true,"db":"up","worker":"up",...}
```

### 2-5. 첫 관리자 계정
운영 DB 에는 샘플 사용자가 없다. 첫 본사 관리자를 만들고 초대 링크를 출력한다.
```bash
docker compose run --rm worker npx tsx scripts/bootstrap-admin.ts "홍길동" admin@company.example
```
출력된 초대 링크(72시간 유효)를 브라우저로 열어 비밀번호를 설정하고 로그인한다. 이후 사용자는 관리 설정 화면에서 등록한다.

(개발·시연용으로 샘플 데이터를 넣고 싶으면 `.env` 에 `ALLOW_SAMPLE_RESET=true`, `SAMPLE_USER_PASSWORD=...` 를 넣고 `docker compose run --rm worker npm run db:seed`.)

## 3. 일상 운영

| 작업 | 명령 |
|---|---|
| 상태 보기 | `docker compose ps` / `docker compose logs --tail=100 web worker` |
| 재시작 | `docker compose restart web worker` |
| 새 버전 배포 | `git pull && docker compose up -d --build` (마이그레이션 자동) |
| DB 백업(수동) | `./scripts/backup.sh` → `backups/` 에 저장 |
| DB 복구 | `./scripts/restore.sh backups/robot_control-YYYYMMDD-HHMMSS.sql.gz` |
| 서버 OS 패치 | `sudo apt-get update && sudo apt-get upgrade -y && sudo reboot` (컨테이너는 자동 재기동) |

지도 이미지는 DB(`map_images`)에 보관되므로 아래 DB 백업에 함께 들어간다.

### 3-1. 자동 백업 (cron)
```bash
crontab -e
# 매일 03:10 DB 덤프, 14일 보관
10 3 * * * cd /opt/robot-system && ./scripts/backup.sh 14 >> backups/backup.log 2>&1
```
이중화: Lightsail 자동 스냅샷(서버 전체) + 일일 DB 덤프(파일). 덤프를 S3/오브젝트 스토리지에도 올리려면 AWS CLI 설정 후 `.env` 에 `BACKUP_S3_URI=s3://버킷/경로` 를 넣는다.
복구 훈련: 분기 1회 테스트 서버에서 `restore.sh` 로 복구가 되는지 확인한다.

### 3-2. 감시 항목
- `https://<도메인>/api/health` 가 200 이 아니거나 본문에 `"worker":"up"` 이 없으면(워커 정지·stale) 알림 — Cloudflare 무료 플랜에는 헬스체크 알림이 없으므로 UptimeRobot 등 무료 외부 감시 또는 Lightsail 지표 알림(CPU·상태 검사)을 사용한다.
- 디스크 사용률 80% 초과(`df -h`), 메모리 부족(`free -m`), `docker compose logs worker` 의 반복 오류.
- 로그인 실패 급증: 관리 설정 → 감사 기록에서 `AUTH:LOGIN` DENIED 를 확인한다.

### 3-3. 키·비밀값 교체
| 대상 | 절차 |
|---|---|
| DB 비밀번호 | `docker compose exec db psql -U robot -d robot_control -c "ALTER USER robot PASSWORD '새값';"` → `.env` 의 POSTGRES_PASSWORD 수정 → `docker compose up -d` |
| 사용자 비밀번호 분실 | 관리 설정 → 사용자 행 → **초대 재발급**(기존 세션 종료) → 링크 전달 |
| 관리자 계정 분실 | `bootstrap-admin.ts` 로 새 관리자 초대 → 로그인 후 기존 계정 정리 |
| 제조사 API 키 | `.env` 의 PUDU_API_APP_KEY/SECRET(또는 CENOBOTS_*, 5단계~) 수정 → `docker compose up -d` (키는 화면에 입력하지 않는다). PUDU CallbackCode 교체 시 `PUDU_CALLBACK_CODE` 도 함께 |
| 세션 전체 무효화 | `docker compose exec db psql -U robot -d robot_control -c "TRUNCATE sessions;"` |

### 3-3-1. PUDU 연동 켜기 (키 발급 후)
1. `.env` 에 `PUDU_API_CLUSTER=sea`, `PUDU_API_APP_KEY`, `PUDU_API_APP_SECRET` 입력 → `docker compose run --rm worker npm run pudu:check` 로 Health Check 통과 확인.
2. 허용 매장 지정: `docker compose run --rm worker npm run pudu:check -- --shops 포스코와이드` 로 우리 매장의 shop_id 를 찾아 `.env` 의 `PUDU_SHOP_IDS=602550006,641450007,...` 에 콤마로 적는다. 대리점 키는 다른 고객사 매장까지 보이므로 **이 값이 없으면 live 로 켜지지 않는다.** 그 다음 `VENDOR_MODE=live`(또는 PUDU 만 `PUDU_MODE=live`) 로 두고 `docker compose up -d`. `npm run pudu:check` 를 다시 실행하면 허용 매장의 로봇만 나온다.
3. 관리 설정 → "제조사 연결 — PUDU Cloud API" → **연결 확인 + 로봇 조회** → 등록할 로봇을 골라 사업장·층에 등록. 이후 워커가 상태(60초)·보고서/장애(10분)·작업/예약/소모품(60분)을 자동 동기화한다. `docker compose logs -f worker` 에 `PUDU status: OK — 로봇 N대 …` 가 찍히는지 본다.
4. 콜백: PUDU(대리점/개발자 플랫폼)에 `https://<도메인>/api/webhooks/pudu` 등록을 요청하고 발급된 CallbackCode 를 `.env` 의 `PUDU_CALLBACK_CODE` 에 넣고 재기동. 등록 전까지는 폴링만으로 동작한다(콜백 endpoint 는 503 응답). Cloudflare 프록시는 이 경로도 그대로 통과시키므로 별도 규칙이 필요 없다.
5. 샘플 데이터가 함께 들어 있어도 PUDU API 에서 등록한 로봇만 실제 API 로 조회·명령하고, 샘플 로봇은 시뮬레이션으로 남는다. 운영 DB 에는 샘플을 넣지 않는 것을 권장한다.
6. 사업장 구성: 관리 설정 → 『사업장 추가』(이름·주소·시간대) → 카드 안에서 『층 추가』 → 『로봇 사업장 이동』으로 등록한 로봇을 층에 배치 → 층의 『PUDU 지도 가져오기』로 실제 지도(이미지·구역)를 연결한다. 지도 이름은 『층#버전#이름』 꼴이므로 층 번호가 맞는 것을 고른다. 이후 로봇 위치가 그 지도 위에 표시된다(`docs/08`).
6. 감시: 관리 설정의 "동기화 상태" 표에서 각 작업의 마지막 실행·성공 시각과 결과를 본다. 실패가 반복되면 `docker compose logs worker` 의 `PUDU … 실패 —` 메시지(문서의 오류 문구 그대로)를 확인한다.

### 3-3-2. PUDU 콜백 등록 (서버 배포 후)
PUDU 는 등록 API 가 없다. 대리점 플랫폼에 URL 을 입력하면 PUDU 가 `callback_code` 를 돌려준다(Quick Start Step 4). 알림은 기본적으로 꺼져 있어 신청이 필요하다.
1. 배포가 끝나 `https://<도메인>/api/health` 가 200 이고 `.env` 의 `APP_BASE_URL=https://<도메인>` 인지 확인한다.
2. 대리점(VD ROBOTICS) 계정으로 대리점 플랫폼 → Application Center → Open Platform 에서 콜백 URL `https://<도메인>/api/webhooks/pudu` 를 입력하고, 아래 요청문으로 콜백 종류 활성화를 요청한다.
3. 돌려받은 `callback_code` 를 `.env` 의 `PUDU_CALLBACK_CODE` 에 넣고 `docker compose up -d`.
4. 관리 설정 → PUDU 패널 → 『콜백 URL 자가 점검』 이 통과하는지 본다(도메인·Cloudflare·프록시 예외·CallbackCode 확인). 이후 로봇이 작업을 시작/종료하거나 장애가 나면 『최근 수신』 시각이 갱신되고 『최근 콜백 이벤트』에 쌓인다.
5. Cloudflare 는 이 경로를 그대로 통과시키면 된다(WAF 규칙으로 막지 않도록). 응답은 5초 안에 200 이어야 하며 우리 endpoint 는 저장만 하고 바로 응답한다.

대리점에 보낼 요청문(예):
> 포스코와이드 청소로봇 통합관제 시스템의 PUDU Open Platform 콜백 등록을 요청드립니다.
> - ApiAppKey: (발급받은 키의 앞 6자리만 적어 식별)
> - 콜백 URL: https://<도메인>/api/webhooks/pudu (HTTPS, 5초 내 200 응답)
> - 활성화 요청 콜백: notifyCleanStatus(청소 작업 상태), TASK_STATUS(예약 작업 상태), notifyRobotStatus(로봇 상태), robotStatus(온라인/오프라인), robotErrorNotice(실시간 장애), robotErrorWarning(장애 집계)
> - 대상 매장: 602550006(선릉센터), 641450007(포스코이앤씨 단기), 637250014(성남분당), 611150001(광양포항 POC)
> 등록 후 발급되는 callback_code 를 전달 부탁드립니다.

### 3-4. 환경 분리
- `APP_ENV=development`(로컬) / `staging`(시험 서버) / `production`. 배너에 환경이 표시되고, production 에서는 쿠키가 secure 로 발급되며 샘플 초기화가 꺼진다.
- 시험 서버가 필요하면 Lightsail 인스턴스를 하나 더 만들고 `.env` 만 바꿔 같은 절차로 띄운다.

## 4. 장애 시
1. `docker compose ps` 로 죽은 컨테이너 확인 → `docker compose logs <이름>`.
2. DB 가 안 뜨면 디스크 용량 확인. 꽉 찼으면 오래된 백업·도커 이미지 정리(`docker system prune`).
3. 서버 자체가 안 되면 Lightsail 스냅샷에서 새 인스턴스를 만들고 고정 IP 를 옮긴다.
4. 데이터가 깨졌으면 최신 덤프로 `restore.sh`.

## 5. 비용 관리
- Lightsail 요금은 고정. 자동 스냅샷·고정 IP(연결 시 무료)·전송량 초과분만 추가.
- AWS 예산(Billing → Budgets)에 월 한도를 걸어 알림을 받는다.
- 크레딧 소진 후 과금이 시작되므로 첫 달 청구서를 확인한다.
