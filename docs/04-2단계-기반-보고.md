# 04. 2단계 "기반" — 구현 보고

작성일: 2026-10-28 · 브랜치: `claude/sharp-bardeen-foe1tf`
범위(인수인계 9장 2단계): 서버 인증 · 사업장별 인가 · 영속 저장 · 감사 이력 · 환경 분리. "UI 에서 숨기는 것만으로 권한 구현 완료 처리 금지".

## 1. 구현 항목

### 영속 저장 — PostgreSQL 16 + Drizzle ORM
- 스키마 `src/lib/db/schema.ts`, 마이그레이션 SQL `drizzle/0000_init.sql`(git 이력 관리). 26개 테이블.
- DB 제약으로 강제한 규칙: 실적 중복 키(제조사+제조사 로봇 ID+제조사 작업 ID 유일), 명령 멱등 키 유일, 보고서(사업장·월·버전) 유일, 이메일 유일, 제조사 이벤트 ID 유일.
- 시각은 timestamptz 로 저장하고 앱에서는 ISO 문자열로 다룬다. 제조사 원시 데이터용 jsonb 열(raw_payload)을 상태·실적·장애에 두었다.
- 1단계 메모리 저장소는 제거했다. 샘플 데이터 생성기는 그대로 두고 `npm run db:seed` 로 DB 에 적재한다.
- 운영 설정(현장 담당자 확정 권한, 명령 만료, 접수 타임아웃, 수신 지연 기준)은 `app_settings` 테이블.

### 인증 — 이메일 + 비밀번호 + 초대 링크 (결정 사항)
- 비밀번호는 Node 내장 scrypt 로 해시(외부 의존성 없음). 정책: 10자 이상, 영문+숫자.
- 서버 세션: DB `sessions` 테이블 + httpOnly 쿠키(운영에서는 secure). 유휴 12시간·절대 30일(환경변수).
- 로그인 실패 5회 → 15분 잠금(환경변수). 없는 계정·틀린 비밀번호·비활성 계정은 같은 메시지로 거부.
- 초대: 본사 관리자가 사용자를 등록하면 72시간 유효한 1회용 초대 링크가 발급된다. 본인이 링크에서 비밀번호를 설정한다. 재발급 시 기존 세션 전부 종료. 이메일 자동 발송은 5단계(현재는 링크를 직접 전달).
- 비활성화 즉시 모든 세션 종료. 매 요청 DB 에서 사용자 상태를 확인하므로 UI 와 무관하게 차단된다.
- 첫 관리자: `scripts/bootstrap-admin.ts` 로 생성(초대 링크 출력). 운영 DB 에는 샘플 사용자를 넣지 않는다.
- 로그인/초대/비밀번호 변경/로그아웃 화면 추가. 미로그인 접근은 `src/proxy.ts` 가 로그인으로 보낸다(낙관적 검사), 실제 검증은 각 화면의 `getCurrentUser()`.

### 인가 — 1단계 규칙 유지, DB 기반으로 재구현
- `src/lib/auth/authz.ts`: 사업장 범위·역할·고객 제어의 명령별 권한·활성 여부. 모든 서비스 함수가 서버에서 검증한다.
- 명령 충돌 정책 **선 조작 우선**(결정 사항): 처리 중 명령이 있으면 본사 명령도 거부.

### 감사 이력
- `audit_logs` 테이블. 명령(거부 포함)·장애 조치·보고서·관리 설정·**로그인 성공/실패/잠금·비밀번호 설정·로그아웃**까지 기록.

### 백그라운드 워커
- `src/worker/main.ts`: 샘플 모드에서 시뮬레이션 틱(명령 요청→접수→실행확인→완료, 하트비트), 공통으로 만료 세션 정리. 3단계부터 제조사 주기 조회·Webhook 후속 처리·예약 실행기가 여기에 붙는다.

### 환경 분리·배포
- `.env.example`: APP_ENV(development/staging/production), DATABASE_URL, 세션·잠금 설정, ALLOW_SAMPLE_RESET, VENDOR_MODE 등. 비밀값은 서버 `.env` 에만.
- Docker: `Dockerfile`(web standalone 타깃 + worker 타깃), `docker-compose.yml`(db·migrate·web·worker·caddy). migrate 서비스가 기동 시 마이그레이션을 먼저 적용. `/api/health` 헬스체크.
- 백업·복구 스크립트(`scripts/backup.sh`, `scripts/restore.sh`), 운영 가이드 `docs/05-배포-운영-가이드.md`(Lightsail·Cloudflare·백업·감시·키 교체).

## 2. 실행 방법 (로컬)
```bash
npm install
cp .env.example .env.local          # DATABASE_URL 을 로컬 PostgreSQL 에 맞게
npm run db:migrate                  # 스키마 적용
npm run db:seed                     # 샘플 데이터 + 샘플 사용자(비밀번호 sample1234!)
npm run dev                         # 웹 http://localhost:3000
npm run worker                      # 다른 터미널: 워커(시뮬레이션·세션 정리)
```
PostgreSQL 이 없으면 `docker compose up -d db` 로 DB 만 띄워도 된다(.env 의 POSTGRES_PASSWORD 필요).

## 4. 완료 / 미완료
완료: 1장 전체. 1단계 7개 화면은 DB 기반으로 그대로 동작한다.

미완료·제한:
- Docker 이미지 빌드·compose 기동은 실제 서버에서 첫 검증 필요(위 표).
- 이메일 자동 발송(초대·알림)은 5단계. 지금은 초대 링크를 직접 전달.
- 2단계 인증(이메일 코드)·SSO 는 추후 검토(결정: 이메일+비밀번호).
- 세션 쿠키는 Cloudflare/Caddy 의 HTTPS 를 전제로 secure 발급(APP_ENV=production).
- 상태 이력(시계열) 테이블은 두지 않았다. 최신 상태 1행만 저장하며, 이력 보관은 3단계 수집 설계 때 보관기간과 함께 정한다.
- 샘플 초기화 중 워커가 동시에 쓰는 경우를 막기 위해 설정 행을 덮어쓰기로 바꿨다. 운영에서는 ALLOW_SAMPLE_RESET=false 로 둔다.
